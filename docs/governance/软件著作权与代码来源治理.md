# DataComplyFlow 软件著作权与代码来源治理

> 用途：形成可核验的代码来源、人工设计决策和第三方资产边界，为软件著作权材料准备、比赛交付和后续研发提供内部证据。本文不是法律意见，最终申报口径应由权利人、代理机构或专业律师确认。

## 1. 治理原则

1. 不通过机械改名、同义替换、拆分语句或插入无意义代码来“伪装”来源；此类操作降低质量，也不能形成真实原创证据。
2. 以产品需求、法律规则建模、Schema 设计、调用链、测试、评测方法和人工评审记录证明项目的独立表达与持续开发过程。
3. AI 辅助生成或修改的代码必须经责任人理解、测试、选择和接受；不得把未复核输出直接标记为完全人工创作。
4. 外部法规原文、译文、模板、论文、UI 生成稿和开源依赖与自研业务代码分开登记，不把外部材料计入自研代码主张。
5. 每次结构优化保持目标单一、测试可复现、commit 可回滚；算法优化与清理、安全修复分开。

## 2. 建议申报源码边界

建议候选源码包以以下活动代码为主：

- `backend/` 中的启动、API、公共基础设施、业务模块、Schema、规则、Workflow、RAG/LLM adapter、Renderer；
- `frontend/src/`、Vite/TypeScript/Tailwind 配置及必要静态资源；
- `scripts/` 中当前有效的构建、评测和维护入口；
- 为理解核心逻辑必要的少量配置示例。

默认不纳入申报源码页数或代码量统计：

- `.venv/`、`node_modules/`、缓存、bytecode、构建输出；
- `outputs/`、Trace、报告、上传文件、数据库和运行时密钥；
- `frontend/tmp/`、`scripts/legacy/`、历史审计快照；
- 法规 PDF/DOCX、论文、比赛说明、外部译文和研究附件；
- 第三方库源码或生成工具自身代码。

是否纳入测试、Prompt、规则表和模板，应结合申报材料要求与权属证明单独决定，不能仅依据“仓库中存在”处理。

## 3. 来源台账 Schema

每一类重要资产至少记录：

| 字段 | 含义 |
|---|---|
| asset_id | 稳定编号 |
| path_scope | 仓库路径或文件集合 |
| asset_type | product_code / generated_ui / legal_source / template / dependency / research |
| origin | 内部设计、外部来源、工具生成、历史迁移等 |
| responsible_person | 需求、实现和复核责任人 |
| first_known_commit | 最早可证明 commit；未知时不得猜测 |
| ai_assistance | none / assisted / generated / unknown |
| human_review | 评审人、日期、测试与接受结论 |
| rights_basis | 自研、许可证、授权、公共领域判断或待确认 |
| license_or_url | 许可证、来源链接或内部授权编号 |
| inclusion_decision | 申报源码纳入 / 运行依赖 / 仅研究 / 排除 |
| notes | 法域、版本、敏感性和其他限制 |

## 6. 形成原创性证据的工程动作

- 保存需求记录、数据结构图、规则决策表、API 契约和交互原型的版本历史；
- 对中国出境路径规则建立“法规依据—事实字段—条件—结果—例外—测试案例”映射；
- 为核心模块保存人工 code review 记录，而不是只保留最终文件；
- 让每个 Bug 修复对应可复现失败和通过测试；
- 建立 Benchmark Case、Gold 标注责任人和数据来源，区分法律专家标注与模型输出；
- 生成 release manifest，记录 commit、依赖锁、规则/Prompt/知识索引 Hash；
- 对第三方 UI、模板、图标、字体、法规译文和外部样本逐项确认许可。

## 7. 软著候选版本门禁

候选版本应至少满足：

1. 工作树干净，具备 annotated release tag；
2. 不含明文凭据、真实上传、运行数据库和未经确认的 Trace；
3. README 启动入口与当前代码一致；
4. 核心测试结果保存，已知失败有清单和风险说明；
5. 活动/Legacy/研究资产边界有文档；
6. 第三方依赖与生成式 UI 完成许可证/条款复核；
7. 代码页选择方式、版本号、软件名称和用户手册保持一致；
8. 权利人已完成人工评审并确认 AI 辅助内容的接受责任。

## 8. 本轮明确不做

- 不进行无意义“降重”或全量变量改名；
- 不声称通过某种修改可以绕过 AIGC 检测；
- 不删除 Git 历史来制造开发过程；
- 不把法规、论文、开源库或生成工具输出直接主张为自研；
- 不在未确认权属时生成最终申报法律结论。
