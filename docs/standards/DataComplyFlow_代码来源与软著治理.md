# DataComplyFlow 代码来源与软著治理

> 类型：代码来源治理知识资产。本文不是法律意见，最终申报口径由权利人和专业人员确认。

## 1. 原则

- 不通过机械改名、同义替换、无意义拆分或代码混淆伪装来源。
- 以需求、规则建模、Schema、调用链、测试、Benchmark、评审记录和 Git 历史证明独立表达与持续开发。
- AI 辅助代码必须由责任人理解、选择、修改和验证；未复核输出不能直接标记为完全人工创作。
- 法规、论文、外部模板、生成式 UI 和开源依赖与自研业务代码分别登记。
- 清理、Bug 修复、结构调整和算法优化分开提交，保持可回滚。

## 2. 候选源码边界

通常纳入：活动 `backend/`、`frontend/src/`、必要配置、当前脚本以及解释核心行为所需的测试、规则和 Prompt。

默认排除：`.venv`、`node_modules`、缓存、构建产物、`storage`、`outputs`、数据库、上传件、Trace、密钥、法规 PDF/DOCX、论文、历史归档、第三方库源码和生成工具输出。

测试、Prompt、规则表和模板是否纳入，应结合申报要求和权属证据单独确认。

## 3. 来源记录最小字段

```text
asset_id
path_scope
asset_type
origin
responsible_person
first_known_commit
ai_assistance
human_review
rights_basis
license_or_url
inclusion_decision
notes
```

`unknown` 在确认前不得改写为“自主研发”。外部法规、模板、论文、图片和历史设计材料不得因为存在于仓库而计入自研代码。

## 4. 当前重点资产

| 范围 | 分类 | 申报前动作 |
|---|---|---|
| `backend/**` | 活动产品代码 | 确认作者、日期、核心评审与测试记录 |
| `frontend/src/**` | 活动产品代码 | 确认交互设计、人工修改与评审责任人 |
| `resources/legal/**` | 外部法律来源及派生语料 | 核验来源、许可、版本和有效期，默认不作为自研源码 |
| `resources/templates/**` | 模板 | 逐项确认原创、授权和实际调用范围 |
| `resources/rules/**`、领域规则 | 规则表达 | 法律团队复核依据，研发确认规则表达形成过程 |
| `pyproject.toml`、`uv.lock`、`frontend/package*.json` | 第三方依赖 | 生成许可证清单并人工复核 |
| `docs/archive/**`、独有研究材料 | 历史或研究资产 | 与候选源码包分离，确认来源和敏感性 |
| 已删除 SuperDesign 预览 | 退役生成式 UI | 不纳入当前产品源码，历史由 Git 和实施记录追溯 |

## 6. 候选版本门禁

候选版本应具备干净工作树和 release tag；不含明文凭据、真实上传、运行数据库和未确认 Trace；README 与入口一致；核心测试结果和已知风险可追溯；活动、兼容、研究和外部资产边界清楚；依赖与外部材料完成许可证复核；权利人完成对 AI 辅助内容的人工接受确认。
