# DataComplyFlow DOCS 活动文档与历史归档收敛契约

## 1. 目标

在不改变业务行为的前提下，将 `docs/` 收敛为现行规范、治理入口、事实快照和必要历史证据四类，消除已完成治理记录继续占据活动入口、历史说明大量失效链接和设计来源文件无扩展名的问题。

## 2. 修改前基线

- `docs/` 共 93 个文件，约 3.65 MB；
- `archive/` 共 64 个文件，约 3.37 MB；
- `governance/` 共 20 个文件，其中 15 个属于已完成批次或结果基线；
- 活动 Markdown 本地断链为 0，归档材料断链为 89；
- `legacy-design-specs/` 保存 12 份设计来源，其中 8 份没有 `.md` 扩展名；
- 后端源码注释共 28 行引用 `认证标准合同路径` 或 `dpia` 两份设计来源；
- 四份 `handoff/` 主文档和 12 份设计来源材料均保留。

## 3. 执行批次

1. `DOCS-01`：把已完成治理契约移入 `archive/governance/executed-batches/`，活动治理目录只保留当前规则；
2. `DOCS-02`：删除无活动引用的旧说明、旧计划、旧测试记录、旧 Prompt/Schema 和历史二进制文档；
3. `DOCS-03`：将设计来源统一放入 `archive/design-provenance/`，为无扩展名文本补充 `.md`，同步更新源码注释路径；
4. `DOCS-04`：验证活动文档链接、仓库卫生、Python 编译和 Git 差异。

## 4. 明确保留

- `docs/engineering/` 全部现行规范；
- `docs/handoff/` 四份主文档及其 README；
- 仓库治理方法论、当前治理计划、模块身份契约和代码来源治理；
- 12 份设计来源材料；
- 本轮及此前已完成治理契约，作为执行追溯证据。

## 5. 明确不做

- 不修改业务代码、接口、Schema、Prompt、规则或测试语义；
- 不把历史设计说明重新认定为当前实现事实；
- 不新增运行时对 `docs/` 的依赖；
- 不执行 Git 提交。

## 6. 验收门禁

- `docs/README.md` 是唯一总入口；
- 活动 `governance/` 不再混放已完成批次记录；
- 活动 Markdown 本地断链为 0；
- 保留的设计来源均具有 `.md` 扩展名；
- 源码注释不再引用旧 `legacy-design-specs` 路径；
- 仓库卫生检查、Python 编译和 `git diff --check` 通过。
