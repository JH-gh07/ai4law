## 1. AI技术路线概述

> 【填写说明】本章总览性回答"AI解决了什么、总体怎么做的、有什么理论依据"。不展开技术细节。

### 1.1 AI解决什么法律业务问题

一段话说明：传统软件系统能解决什么（规则判断、流程管理、文件处理），AI在哪些环节不可或缺（语义理解、法规检索匹配、文书生成、条款审查），以及为什么不能用纯规则替代。

| 业务环节 | 传统系统能力 | AI增强能力 | 不可替代原因 |
|---|---|---|---|
| 法规检索 | 关键词匹配 | 语义理解+跨法域检索 | 同义不同词、跨语言 |
| 路径判断 | 确定性规则 | 缺失信息推理、一致性复核 | 边界案例需语义判断 |
| 报告生成 | 模板填充 | 自然语言段落生成 | 每个案例事实不同 |
| 条款审查 | 格式检查 | 合规风险识别、修改建议 | 风险需要法律语义理解 |

### 1.2 总体AI技术路线

用一段文字和流程图说明：**规则引擎（确定性） + RAG检索（依据） + LLM生成（表达） + 校验（质量）** 的总体路线。

```text
用户输入
  → 规则引擎（确定性判断 true/false）
  → RAG检索（语义+关键词混合，本地+云端双源）
  → 上下文组装（规则结果 + 检索依据 + 用户事实）
  → LLM生成（Prompt约束下的受控生成）
  → 后处理校验（引用正确性、事实一致性）
  → 报告输出
```

### 3.1 RAG知识检索体系

#### 3.1.1 知识库建设

说明知识库规模（69个来源、1,672条条文）、索引类型（15个逻辑索引，5类资源×3法域）、构建流程。

#### 3.1.2 多索引检索技术

说明检索流程：查询→分词→SHA-256哈希向量（384维）→向量相似度+关键词→RRF融合→UsagePolicyFilter→结果返回。

关键技术细节：确定性哈希替代进程随机hash（引自具体实现），索引版本管理，不兼容自动重建。

#### 3.1.3 检索增强生成调用链

```text
用户查询
  → QueryPlan（确定法域、资源类型、检索策略）
  → 本地多索引检索（legal/workflow/standard_clause/template/testcase）
  → 置信度判断
    ├─ 充分 → 直接注入上下文
    └─ 不足/HIGH风险 → 触发得理API增强
       → 来源对齐 → 效力校验 → 入库候选
  → 上下文组装（规则结果+检索结果+用户事实）
  → 注入LLM Prompt
```

#### 3.1.4 外部法律API集成

说明得理API的集成方式：条件触发（置信度不足/高风险/用户要求）、归一化处理、来源对齐、候选入库流程。标注当前适配器已知限制（丢失稳定ID、条号、效力状态）。
