## 文档职责边界速查

| 如果内容涉及… | 应写入 | 不应写入 |
|---|---|---|
| 行业背景、用户画像、业务场景展示 | 需求分析文档 | SRS / 设计 / 实现 |
| 功能列表、数据字段、约束条件、验收标准 | 需求说明文档(SRS) | 设计 / 实现 |
| 架构分层、组件职责、接口契约、质量机制 | 方案设计说明书 | 需求 / 代码文件 |
| 目录、文件、类、函数、配置、部署命令 | 具体实现说明书 | 需求论证 / 测试结果 |
| 测试用例、执行结果、缺陷、回归、质量结论 | 系统测试文档 | 需求 / 实现代码 |
| Prompt全文、模型实验、Token明细、AI评测 | AI综合说明文档 | 普通功能的需求和设计 |
| 功能清单、模块能力概述 | 软件功能说明文档 | 展开设计 / 测试细节 |
| 演示脚本、展示路径、关键界面 | 产品演示文档 | 完整操作教程 |
| 页面操作步骤、字段说明、截图 | 用户使用手册 | 技术架构 |

## 编写原则（9项AI审查规则）

1. 软件工程主线要完整——文档必须形成完整闭环
2. 文档主线要唯一——一份文档只能有一条主要组织逻辑
3. 章节职责要互斥——每章只回答一个核心问题
4. 同级标题要同一维度——同一层级统一分类标准
5. 内容分合要有依据——不同目的/来源/阶段的内容分开
6. 标题层级要匹配体量——内容过少不单独成节
7. 通用结构和项目内容要分层——骨架稳定，项目内容下沉
8. 正文、表格和附录要合理分工——正文讲逻辑，表格存明细，附录存资产
9. 标准用于校验而不是照抄——不机械复制大型企业目录

## 使用方式

1. 阅读对应提纲，理解章节职责和填写说明
2. 根据 `【填写说明】` 指引，结合项目事实填充内容
3. 填充后执行 AI 结构审查（按9项规则检查）
4. 定稿前确认与相邻文档无重复、无断层
