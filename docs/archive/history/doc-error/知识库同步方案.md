## 第一步：CSV Schema 重新设计

### 当前 `sources.csv` 字段

```
source_id, layer, jurisdiction, path, doc_type, title, source_org,
authority_level, publish_date, effective_date, status, url,
snapshot_path, usage_priority, notes
```

### 需新增字段（补齐前端展示所需）

| 新字段名 | 类型 | 含义 | 示例 |
|----------|------|------|------|
| `category` | string | 内容分类 | `"核心法律"` / `"部门规章"` / `"官方指南"` / `"标准规范"` / `"模板文书"` |
| `usage` | string | 使用方式（替代 `usage_priority`） | `"审查基准"` / `"条文匹配"` / `"知识增强"` / `"参考引用"` |
| `binding_force` | string | 约束力 | `"强制"` / `"建议"` / `"参考"` |
| `authority` | string | 权威等级（替代 `authority_level`） | `"高权威"` / `"中权威"` / `"参考"` |
| `publisher` | string | 发布机构（替代 `source_org`） | `"国家互联网信息办公室"` |
| `summary` | string | 内容简介（一段中文概述） | `"《数据出境安全评估办法》建立了..."` |
| `suitable_for` | string | 适用场景 | `"评估申报"` / `"路径判断"` / `"SCC审查"` / `"BCR审核"` … |
| `report_usage` | string | 正式报告中的使用方式 | `"可直接引用条文号"` / `"需附带解释说明"` / `"仅供分析参考"` |

### 字段迁移计划（不破坏现有 CSV）

**策略：新增字段，不删除旧字段。** 保持向后兼容。后端 `knowledge_projection.py` 在读 CSV 后做字段映射，前端完全不感知 CSV 原始字段名。

```
CSV 原始字段          映射后字段（前端可见）
─────────────────    ─────────────────────
source_org      ──→  publisher
usage_priority  ──→  usage（映射表翻译 P0→"审查基准"）
authority_level ──→  authority + binding_force（按规则拆分）
新增 category   ──→  category
新增 summary    ──→  summary
新增 suitable_for →  suitable_for
新增 report_usage →  report_usage
```

### 最终 `sources.csv` 字段清单（16 列）

```
source_id, jurisdiction, path, category, doc_type, title,
publisher, authority, binding_force, publish_date, effective_date,
status, url, snapshot_path, usage, suitable_for, report_usage, summary, notes
```

## 第三步：后端字段映射层

### 位置

`backend/services/knowledge_projection.py` — 所有前端可见数据都经过此文件。

### 改动点

目前 `build_user_source_catalog()` 是直接从 CSV `dict` 透传。需在返回前做映射。

```python
# 字段映射规则（写在 knowledge_projection.py 顶部）
USAGE_MAP = {
    "P0": "审查基准",
    "P1": "条文匹配", 
    "P2": "知识增强",
    "P3": "参考引用",
}

BINDING_MAP = {
    "law":          "强制",
    "regulation":   "强制",
    "guideline":    "建议",
    "standard":     "建议",
    "template":     "参考",
}

AUTHORITY_MAP = {
    "official":     "高权威",
    "judicial":     "高权威", 
    "standard":     "中权威",
    "guideline":    "中权威",
    "template":     "参考",
}

def _normalize_source_row(row: dict) -> dict:
    """将 CSV 原始字段映射为前端一致命名。
    
    规则：
    - source_org → publisher
    - usage_priority → usage（通过映射表翻译）
    - doc_type → binding_force
    - authority_level → authority
    - 新增字段直接透传
    """
    return {
        **row,
        "publisher":     row.get("source_org") or row.get("publisher", ""),
        "usage":         USAGE_MAP.get(row.get("usage_priority", ""), 
                                       row.get("usage", "")),
        "binding_force": BINDING_MAP.get(row.get("doc_type", ""), "参考"),
        "authority":     AUTHORITY_MAP.get(row.get("authority_level", ""), 
                                           row.get("authority", "中权威")),
    }
```

### 不影响现有 API 契约

`/api/v1/knowledge/index` 返回的 JSON Schema 不变，只是各字段有了值。

## 第四步：正文可用性校验

### 问题

CSV 中 `snapshot_path` 指向的实际文件可能：
- 不存在
- 路径错误
- 内容为空

### 方案

在 `/api/v1/knowledge/sync` 中增加一步：

```python
def _validate_snapshots(rows: list[dict]) -> dict:
    """返回每条 source 的快照可用性。"""
    status = {"total": len(rows), "ok": 0, "missing": 0, "broken": []}
    for row in rows:
        path = row.get("snapshot_path", "").strip()
        if not path:
            status["missing"] += 1
            status["broken"].append({"id": row.get("source_id"), "reason": "no path"})
            continue
        full = (ROOT / path).resolve()
        if not full.exists():
            status["missing"] += 1
            status["broken"].append({"id": row.get("source_id"), "path": str(full), "reason": "file not found"})
            continue
        try:
            content = full.read_text(encoding="utf-8")
            if not content.strip():
                status["broken"].append({"id": row.get("source_id"), "path": str(full), "reason": "empty file"})
                continue
            status["ok"] += 1
        except Exception:
            status["broken"].append({"id": row.get("source_id"), "path": str(full), "reason": "read error"})
    return status
```

这个校验结果在 `/index` 和 `/sync` 响应中作为 `sync_meta.snapshot_status` 一起返回。

前端 EvidenceCenterPage 的同步状态卡片新增一行：
```

```

## 第五步：模块-法规关联展示（P2，可选）

### 当前状态

`module_catalog.v1.json` 中每个模块声明了自己的 `indexes` 和 `stages`，但前端知识库中心完全不展示"这条法规被哪些模块引用"。

### 方案

在后端 `knowledge_projection.py` 中新增一个函数：

```python
def _build_module_law_index(catalog: dict, sources: list[dict]) -> dict[str, list[str]]:
    """返回 {source_id: [module_names]} 的映射。"""
    from backend.common.knowledge.registry import load_module_catalog
    result: dict[str, list[str]] = {}
    for module_name, module_def in catalog.get("modules", {}).items():
        indexes = module_def.get("indexes", [])
        # 根据每个模块依赖的 legal_index 推断它需要哪些法条
        for source in sources:
            jur = source.get("jurisdiction", "")
            if f"legal_index_{jur}" in indexes:
                sid = source.get("source_id")
                if sid:
                    result.setdefault(sid, []).append(module_name)
    return result
```

在 `/api/v1/knowledge/sources/:id` 响应中新增字段 `used_by_modules: ["cn_review", "cn_assessment"]`。
