## 7.1 更正记录（2026-08-08 追加）

本报告原先声称"正文脚注编号和 CitationMap 完全一致"。**该结论当时没有证据支持，现予更正。**

原因：本次首跑直接构造 `ChapterContent`，绕过了 `chapter_generator.py:445` 的
`convert_citation_markers` 调用。因此：

- 章节正文保留原始 `{{CIT-*}}` marker，未转成 `[N]`；
- `citation_registry.assign_footnote_number` 从未被调用，`footnote_map` 为空（0 条）；
- §14.1 的阻断项"正文脚注和 CitationMap 数量不一致"在该 harness 下**无法被触发**——
  两侧都是空集，恒等成立，等于没有验证。

进一步排查发现这不只是 harness 缺陷，而暴露了 ISSUE-reporting-001：
两个 schema-first 适配器都只识别 `{{CIT-*}}`，遇到生产形态 `[N]` 会抛
`ValidationError`。详见 `status/check/ISSUE-reporting-001_引用形态不匹配_20260808.md`。

修复后（提交 `96df783`）已用生产形态内容复验，DPIA 侧结果：

| 检查 | 结果 |
|---|---|
| 正文 `[N]` 集合 | `['1']` |
| `citation_map.footnote_map` 键集合 | `['1']` |
| 两者一致 | ✅ True |
| 原始 marker 残留 | 0 |

assessment 侧已由 `test_production_footnote_shape_yields_claim_block_with_refs`
（`backend/domains/cn/security_assessment/tests/test_schema_first_adapter.py`）锁定生产形态，
但**尚未重跑 assessment 的完整产物首跑**。因此 assessment 的"引用一一对应"一项
当前状态为**部分验收**，不是已完成。

## 7.2 生产形态复查（2026-08-08 追加）

已于提交 `57415f4` 完成 assessment 的生产形态首跑复查。新增
`test_schema_first_renderer.py`，包含 5 项集成测试：

| 测试 | 验证内容 | 结果 |
|---|---|---|
| `test_production_form_with_schema_first_generates_document_ir` | 8章生产形态 `[N]` 脚注 → ClaimBlock citation_refs → document_ir.json → citation_map.json → ZIP 包含 document_ir | ✅ |
| `test_production_form_without_schema_first_omits_document_ir` | schema_first=False 时不生成 document_ir.json | ✅ |
| `test_production_form_block_count_invariant` | 两次运行 Block 结构一致 | ✅ |
| `test_compiler_blocks_unregistered_citation_in_production_form` | 未注册 `[999]` 被编译器阻断（CITATION_NOT_REGISTERED） | ✅ |
| `test_citation_map_footnote_count_matches_body_references` | DocumentIR citation_refs == citation_map footnote_map CIDs | ✅ |

**核心证据**：

- 正文含有 `[1]`、`[2]`、`[3]` 三个生产形态脚注（8 章中含 5 个 ClaimBlock，3 个 ParagraphBlock）
- DocumentIR 中 `citation_refs` = `['CIT-CN-EXPORT-ASSESSMENT-ART5-P01', 'CIT-CN-PIPL-ART13-P01', 'CIT-CN-CYBERSEC-ART6-P01']`
- `citation_map.json` 的 `footnote_map` 键 = `['1', '2', '3']`，与正文引用完全一致
- Compiler diagnostics = `[]`，status = `success`
- 旧流程（schema_first=False）不产出 document_ir.json，回退正常

**同时修复**（提交 `c787594`）：所有 8 个 schema_first 适配器统一处理
unresolvable `[N]` residue——适配器不再让未注册脚注进入 ParagraphBlock 导致
ValidationError，而是将其提升至 ClaimBlock 让编译器触发 CITATION_NOT_REGISTERED。

因此 assessment 的"引用一一对应"一项现在状态为**已完成**。
