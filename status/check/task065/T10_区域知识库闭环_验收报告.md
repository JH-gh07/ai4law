## 三、验收标准逐条核对

### 1. CSV/registry source_id 集合相等

```text
sources.csv        : 120 entries（69 主 + 51 区域）
source_registry.v1.json : 120 entries
build_source_registry.py --check : only-in-cache 0 / only-in-csv 0 / field deltas 0 → OK
```

`regulation_articles.jsonl` 为条文层（法律/法规可抽取正文才有条文），区域 33 个 source_id 有正文条文；
VN 6 份为图片型 PDF（无可抽取文本层），按「可预览、暂不参与结构化检索」降级为 `preview_only`，
与 CN/EU/US 的 template/guide/support 类条目同口径。

### 2. 51 个 PDF 一对一

```text
区域 registry 条目               : 51
有 snapshot_path（绑定到 PDF）   : 49
无 PDF 的 source（专家评审缺口） : JP-LAW-009、KR-GUIDE-006
无 source 归属的 PDF（冗余版本） : jp/references/B01_1_...失效.pdf、kr/references/A04_1_...附表.pdf
```

49/49 有 PDF 的条目已一一绑定；剩余 2 source + 2 冗余 PDF 是法域数据质量缺口，需法域法律专家评审后
补充/裁定（详见第四节），不阻塞索引与浏览闭环。

### 3. 区域查询不污染默认 CN/EU/US 模块

- 区域 registry 条目 `modules == []`：`true`
- 区域 chunk `module == ""`：`true`
- `RetrievalOrchestrator.retrieve(module="cn_assessment", ...)` 返回法域仅 `cn`（205 chunks，0 区域）
- `search_user_articles(query, jurisdiction="sg")` 只检索 `legal_index_intl`，命中法域仅 `sg`

### 4. Evidence Center 按法域打开条文并返回合法 citation

- `build_user_source_catalog()` 产出 118 条（69 主 + 49 区域，2 条 metadata ghost 按设计排除）
- `get_user_source_preview("SG-LAW-001")` 返回 PDPA 正文（不再是二进制乱码）
- `get_article_detail("SG-LAW-001", "3")` 返回 `jurisdiction=sg`、`doc_type=law`、`source_url=https://sso.agc.gov.sg/Act/PDPA2012`、正文条文

## 四、剩余数据质量缺口（需专家评审，不在本轮代码闭环内）

1. **JP-LAW-009（重要经济安保信息保护与利用法）**：sources.csv 有 metadata，但 `references/` 无对应 PDF。
2. **KR-GUIDE-006（儿童个人信息保护指南）**：sources.csv 有 metadata，但 `references/` 无对应 PDF。
3. **2 份冗余 PDF 未归属**：`jp/B01_1_...失效.pdf`、`kr/A04_1_...附表.pdf`（同一法律的失效版/附表版）。
4. **JP/KR 部分 title 与 PDF 内容不符**：例如 CSV `JP-LAW-008` title 为「电气通信事业法」，实际 PDF 为「网络安全基本法」；
   `KR-GUIDE-004/005` 与 `A04_2/A06` 文件名语义需人工核对。这是元数据质量而非代码缺陷，须经法域法律专家签署后再修正。
