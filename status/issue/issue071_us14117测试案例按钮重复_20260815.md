## 一、问题概述

前端各模块 Wizard 里，开发期快速测试存在 **两类并存的入口**，功能高度重叠：

- **A 类 · 顶部「🧪 测试案例」**：打开案例选择器，从 `dev-test-cases.ts` / `benchmarks/cases/**/scenario.json` 选案例回填表单（不自动运行）。
- **B 类 · 底部「一键体验/一键运行」**：注入 `dev-presets.ts` 的预置数据 + 预置附件，**直接调后端执行**（不回填、直接跑）。
- **C 类 · us_14117 底部额外的「🧪 测试案例」**：与 A 类完全相同的入口，仅因放在底部运行条而多出。

三者均受 `DEV_ACCEL_ENABLED`（`VITE_ENABLE_DEV_ACCEL=true`）控制。

> **影响范围限定**：本问题仅在开发者模式（`VITE_ENABLE_DEV_ACCEL=true`）开启时暴露；关闭开发者模式时，A/B/C 三类入口全部隐藏（渲染为 `null`），生产环境不出现这些按钮。

### 6.3 关键结论

1. `seed-cases-v1`（docx，51 文件 = 10 task × 5 case + 黄金标准 + 分数汇总表）是**原始种子素材，未接入前端**，仅作溯源源头存在。
2. 前端「🧪 测试案例」实际读的是 `benchmarks/cases/**/scenario.json`（结构化 JSON）：`dev-test-cases.ts` 共 import **20 个** scenario.json，另有 **8 个内联案例**（`formDefaults` / `backendFilePaths` 直接硬编码在 `dev-test-cases.ts`），合计 **28 个前端案例**。`benchmarks/cases/bcr/` 下 2 个 scenario.json 存在但**未 import 进前端**。
3. 两层之间靠 `dev-test-cases.ts` 注释链关联（source-material docx → `seed-cases-v1/_source/taskNN_caseM.docx` → 前端案例），但**运行时从不读 docx**，只读 scenario.json 的 `request` 字段（驱动 `formDefaults` + `backendFilePaths`）。
