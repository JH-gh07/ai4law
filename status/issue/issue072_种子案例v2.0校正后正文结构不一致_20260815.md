# issue072 — 种子案例 v2.0 校正后 8 个 case1/2 输入段抽空（Level A 只装输入侧）

> **日期**: 2026-08-15
> **严重程度**: P1（输入侧抽取为空，阻塞 Level B）
> **关联文件**:
> - `scripts/build_seed_case_inputs.py`
> - `benchmarks/datasets/seed-cases-v1/_source/task04|06|07|08/`（8 个 case1/2 docx，已覆盖 v2.0）
> - `benchmarks/datasets/seed-cases-v1/inputs/task{04|06|07|08}_case{1|2}.input.json`（当前 input 为空）

---

## 一、问题

任务 4/6/7/8 的任务名已按 v2.0 改对（文档审查 / BCR 审查 / DPIA 草案生成 / TIA 草案生成），8 个 case1/2 docx 已用 v2.0 内容覆盖。但重跑 Level A 后，这 8 个文件的 **`input.paragraphs` 全是空**——输入段没抽出来。

## 二、根因

脚本硬编码的输入标记是 v1.0 的：

```python
MARK_INPUT = "一、用户输入"
```

v2.0 这 8 个文件的输入段写法对不上，`startswith` 匹配不到起点，于是输入段被切成空。

## 三、8 个文件的输入段（三种写法）

| 写法 | 文件 | 输入段 |
|---|---|---|
| `用户输入`（少了「一、」） | task07_case1/2、task08_case1/2 | 标记之后 → 输出标记之前 |
| `待审查的BCR条款原文` | task06_case1/2 | 标记之后 → 文末（无输出段） |
| 无标记（文档正文） | task04_case1/2 | 文档标题起 → 输出标记之前 |

## 四、真正的需求

1. **input.json 只装输入侧文本，不装输出/标准答案**（输出是 expected 阶段的事）。
2. 所以本 issue 只做一件事：**把 8 个文件的输入段正确抽出来**。
3. 输出侧的问题（task4 金标是图片、task6 无金标）**不涉及、不阻塞**，另行处理。

## 五、改法（只改脚本的输入段识别）

1. 输入标记候选：`一、用户输入`、`用户输入`、`待审查的BCR条款原文`。
2. 输入终点：到第一个输出标记为止；全文无输出标记则到文末。
3. 兜底：找不到输入标记时，以文档开头作为输入起点，到输出标记为止。

**输出段不改、不写进 input.json。**
