## Fix 1: 半截窗口 — 动态高度 + 独立折叠区

### 目标
Trace in Copilot 面板从固定 288px → 动态分配可用空间，同时允许用户手动收折以恢复聊天空间。

### 修改清单

#### 1.1 CSS: 提升 max-height 上限并按视口自适应

**文件**: `frontend/src/styles/app/workspace.css`

**当前代码** (line 4231-4239):
```css

  min-height: 0;
  min-width: 0;
  overflow-y: auto;
  overflow-x: hidden;

  border-top: 1px solid rgba(217, 228, 241, 0.9);
```

**修改为**:
```css
.copilot-trace-inline-body {
  --trace-max-h: min(
    calc(50vh - 8rem),          /* 视口高度的一半减去标题栏等固定空间 */
    32rem                        /* 绝对上限 ~512px，约 6-8 个节点 */
  );
  max-height: var(--trace-max-h);
  min-height: 0;
  min-width: 0;
  overflow-y: auto;
  overflow-x: hidden;
  padding: 0.1rem 0.08rem 0.3rem;
  border-top: 1px solid rgba(217, 228, 241, 0.9);

/* 当 Trace 节点数 ≤ 4 时，自适应高度避免空白 */

  max-height: none;
```

**变更说明**:
- `18rem` → `min(calc(50vh - 8rem), 32rem)`: 在小屏 (768px) 上约 256px，在大屏 (1080px+) 上约 512px
- 新增 `[data-node-count]` 自适应规则：节点少时不浪费空间
- 兼容性：CSS `min()` 和 `calc()` 在 2020 年后所有主流浏览器均已支持

## Fix 2: 延迟显示 — 连接策略优化

### 目标
SSE 正常时首条事件到达延迟从 ~500ms → ~200ms；SSE 失败时从 3s 空白 → 即时显示骨架屏 → 0.8s 后切换到轮询。

### 修改清单

#### 2.1 缩短轮询 fallback 初始延迟

**文件**: `frontend/src/lib/useTaskEvents.ts`

**当前代码** (line 279):
```typescript
const INITIAL_FALLBACK_DELAY_MS = 3000;
```

**修改为**:
```typescript
const INITIAL_FALLBACK_DELAY_MS = 800;
```

**理由**: 在局域网或本地开发环境下，Token 请求 + EventSource 握手通常在 200-500ms 内完成。800ms 是在"给 SSE 足够时间"和"尽快启用轮询"之间的平衡点。生产环境跨地域部署时，Token 请求可能 1-2s，此时 800ms 后轮询会先拉取已有事件，SSE 建立后再切回推送。

#### 2.2 在 SSE 连接建立前先启动即时轮询

**当前流程** (line 262-296):
```
useEffect → 注册 listener → 尝试 SSE → 3s 后检查 SSE 状态 → 未成功则启动轮询
```

**修改为**:
```typescript
useEffect(() => {
  if (!taskId) return;

  // Register listener
  if (!listeners.has(taskId)) {
    listeners.set(taskId, new Set());
  }
  listeners.get(taskId)!.add(setEventsAndNotify);

  // ✅ 新增：立即加载已有事件（localStorage/IndexedDB 持久化缓存或
  //    从 eventBuffers 中获取——连接建立前也能显示历史事件）
  const existing = eventBuffers.get(taskId);
  if (existing && existing.length > 0) {
    setEvents([...existing]);
  }

  // ✅ 修改：不等待 SSE，立即启动轮询（SSE 建立后会自动停止轮询）
  //   轮询作为"第一时间数据通道"，SSE 作为升级
  void ensureSSE(taskId);
  ensurePolling(taskId);  // ← 立即启动轮询，不再等 3s

  // 保留但缩短的 fallback 用于 SSE 重连场景
  const fallbackTimer = setTimeout(() => {
    if (hasTerminalEvent(taskId)) return;
    const es = eventSources.get(taskId);
    if (!es || es.readyState !== EventSource.OPEN) {
      // 确保轮询仍在运行（上面的 ensurePolling 可能已被 stopPolling 清除）
      ensurePolling(taskId);
    }
  }, INITIAL_FALLBACK_DELAY_MS);  // 800ms

  return () => {
    clearTimeout(fallbackTimer);
    const taskListeners = listeners.get(taskId);
    taskListeners?.delete(setEventsAndNotify);
    if (!taskListeners || taskListeners.size === 0) {
      listeners.delete(taskId);
      stopTaskTransport(taskId);
    }
  };
}, [taskId, setEventsAndNotify]);
```

**关键变化**:
- 轮询**立即启动**（不等待 SSE），作为第一时间数据通道
- SSE 的 `es.onopen` 回调中已有 `stopPolling(taskId)`（line 200），SSE 建立后自动停止轮询
- SSE 失败时 `es.onerror` → `scheduleReconnect` → `ensurePolling` — 轮询作为持续性 fallback
- `ensuePolling` 内部已有幂等保护（`pollingCleanups.has(taskId)` 检查，line 140-141），多次调用安全

## Fix 3: 截断/省略 — 阈值调整 + "N项未显示"提示

### 目标
- 文本截断阈值从 120 提升至 300 字符
- 数组截断从 6 项提升至 20 项，附带 `还有 N 项未显示`
- 对象 key 截断从 8 提升至 24
- 预览行数从 8 提升至 15
- 所有截断点都提供"仍有更多内容"的提示

### 修改清单

#### 3.1 文本截断阈值调整

**文件**: `frontend/src/lib/trace-adapter.ts`

**当前代码** (line 37-39):
```typescript
function shorten(value: string | undefined, limit = 120): string | undefined {
  if (!value) return undefined;
  return value.length > limit ? `${value.slice(0, limit - 1)}…` : value;
}
```

**修改为**:
```typescript
const SHORTEN_DEFAULT_LIMIT = 300;
const SHORTEN_SHORT_LIMIT = 80;   // 用于 tool name、category 等短标签

function shorten(value: string | undefined, limit = SHORTEN_DEFAULT_LIMIT): string | undefined {
  if (!value) return undefined;
  if (value.length <= limit) return value;
  // 在单词边界截断，避免截断到中文/英文单词中间
  const truncated = value.slice(0, limit);
  // 从后往前找最近的空格或中文标点作为截断点
  const breakPoints = [" ", "。", "，", "；", "：", "、", "\n", ".", ",", ";"];
  let cutIndex = limit;
  for (const bp of breakPoints) {
    const lastIndex = truncated.lastIndexOf(bp);
    if (lastIndex > limit * 0.5) {
      cutIndex = Math.min(cutIndex, lastIndex);
    }
  }
  return `${truncated.slice(0, cutIndex).trimEnd()}…`;
}
```

**调用点不动**：`summaryLine()` → `shorten(value, SHORTEN_DEFAULT_LIMIT)`、`makeNode()` description → `shorten(event.summary, 200)`、`semanticFromDetail` tool name → `shorten(name, 40)` 保持不变。
