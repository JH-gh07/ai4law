# 引用跳转：移除 Drawer，直连知识库中心

> 日期：2026-08-09
> 状态：方案，待执行

## 目标

点击报告正文中的 `[N]` 脚注或 `【依据：法规名 第X条】` 时，**不再弹出 CitationArticleDrawer 侧边抽屉**，直接跳转到知识库中心（`/evidence`），让用户在法规证据总览的上下文中查看引用来源。

## 当前流程（要废弃的）

```
正文 [1] 按钮
  → CitationPopover (hover 浮层，展示 标题/条号/引用摘要/定位状态/对外策略)
  → 点击按钮 → handleOpenCitation → setSelectedCitation
  → CitationArticleDrawer (右侧抽屉)
      ├── exact_article: 调 fetchArticleDetail → 展示上文/当前条文/下文
      ├── source_overview: 展示失败原因
      ├── external_verified: 展示失败原因
      └── unresolved: 展示失败原因
      └── 底栏按钮: "在知识库中继续阅读" / "查看法规概览" → navigate
```

**问题**：两层浮层（Popover + Drawer）打断阅读流，用户在报告和抽屉之间反复切换。

## 目标流程

```
正文 [1] 按钮
  → CitationPopover (hover 浮层，保留，展示 标题/条号/定位状态/对外策略)
  → 点击按钮 → navigate(`/evidence?source={sourceId}&article={no}`)
  
正文 【依据：个人信息保护法 第十三条】
  → 解析 + fetchKnowledgeCitation + fetchArticleDetail 验证
  → 点击按钮 → navigate(`/evidence?source={sourceId}&article={no}`)
```

**效果**：一次点击，浏览器地址栏变化，用户进入 `/evidence` 页面，该法规来源自动展开，条文自动定位。无侧边抽屉，不打断上下文。

## 改哪些文件

### 1. `frontend/src/components/citation/CitationMarkdownRenderer.tsx`

| 改动 | 说明 |
|---|---|
| 删除 `selectedCitation` 状态 | 不再需要 |
| 删除 `<CitationArticleDrawer>` 渲染 | 删掉 return 末尾的 `{selectedCitation ? ...}` |
| 删除 `import { CitationArticleDrawer }` | — |
| 改造 `handleOpenCitation` | 从 `setSelectedCitation(citation)` 改为 `navigate(\`/evidence?source=${citation.source_id}&article=${citation.article_no}\`)` |
| 新增 `import { useNavigate }` | 获取 navigate 函数 |
| Popover 的 `onClickSource` 回调 | 不变，仍传 `handleOpenCitation`（但函数体内逻辑变了） |

### 2. `frontend/src/pages/EvidenceCenterPage.tsx`

需要支持 URL 查询参数 `?source=xxx&article=yyy`：

| 改动 | 说明 |
|---|---|
| 读取 `useSearchParams` | 获取 `source` 和 `article` 参数 |
| `useEffect` 自动展开 | 检测到 `source` 参数时，自动调用 `setSelectedSourceId(source)`，展开右侧详情面板 |
| 条文定位 | 检测到 `article` 参数时，在详情面板中自动滚动/高亮到对应条文 |
| 参数来源 | 不是所有法规来源都在知识库中——`source_id` 不在 `sources.csv` 中的，仅显示"外部来源"提示 |

### 3. `frontend/src/components/citation/CitationPopover.tsx`

| 改动 | 说明 |

### 4. `frontend/src/components/citation/CitationArticleDrawer.tsx`

### 5. `frontend/src/api/knowledge.ts` 中的 `fetchArticleDetail`

保留不删——`CitationMarkdownRenderer` 的 `buildResolvedCitation` 仍需要它来验证条文唯一性、确定 `can_jump` 和条号。

### 6. `buildResolvedCitation` (在 `CitationMarkdownRenderer.tsx` 内)

## EvidenceCenterPage 的 query 参数支持

```
/evidence
  → 正常进入，默认视图（全部法规卡片列表）

/evidence?source=CN-LAW-003
  → 自动展开 CN-LAW-003 的详情面板
  → 如果 source_id 不在知识库中，显示"外部来源提示"

/evidence?source=CN-LAW-003&article=13
  → 自动展开 CN-LAW-003 详情面板
  → 自动滚动到第十三条并高亮
```

## 不变的部分

- `CitationPopover` 的 hover 浮层**完全保留**——标题、条号、引用摘要、定位状态（exact_article/source_overview/external_verified/unresolved）、对外引用策略、低置信度警告全部不变
- `fetchCitationMap` 的加载和缓存不变
- `【依据：】` 的两级解析（citationMap 模糊匹配 → fetchKnowledgeCitation 检索 → fetchArticleDetail 唯一性验证）不变
- `canJump` 的判断逻辑不变

## 验收标准

1. 点击报告中的 `[N]` 脚注 → URL 变为 `/evidence?source={sourceId}`，页面跳转到知识库中心
2. `exact_article` 跳转带 `?article={no}`，`source_overview` 不带 article 参数
3. `/evidence` 页面接收到 `?source=` 后自动展开对应来源的详情
4. `/evidence` 页面接收到 `?article=` 后自动滚动到对应条文
5. Hover Popover 仍然正常展示（标题、条号、定位状态、对外策略）
6. `not_found` / `not_unique` / `missing` 的引用，hover 仍显示中文原因
7. 删除后没有残留的 Drawer 代码、CSS 类名、e2e 断言引用
8. 现有 npm test 和 e2e 测试通过（或按本方案修改后通过）
