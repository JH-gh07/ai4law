# 060 生成内容与报告模板专项审计

> 日期：2026-08-12
> 状态：现状分析与审计任务拆分阶段
> 范围：需求文档、黄金示例、业务规则、模型生成、章节拼接、报告模板和最终产物
> 原则：只在本地核验；Claude Code 的工作区改动必须经过独立审查后才能视为完成

## 本大阶段目标

确认系统最终生成的报告，是否真正符合最初需求文档和黄金示例的业务目的，而不是只满足“有章节、有文件、测试通过”。重点检查：

- 生成内容是否回答了正确的业务问题；
- 报告结论是否来自事实、规则和证据；
- 模型、规则和模板是否重复生成或重复拼接；
- 不同章节之间是否重复、矛盾或互相覆盖；
- Markdown、DOCX、PDF 和 JSON 是否来自同一份内容；
- 不同功能是否保留业务差异，而不是被同一模板强行同质化。

## 三个小任务

| 文件 | 目标 | 产出 |
|---|---|---|
| `060task_01_需求与生成现状基线分析_20260812.md` | 列出现状、文件职责、来源依据、当前候选改动和未验证事实 | 现状基线与文件清单 |
| `060task_02_生成内容与模板拼接重复审计_20260812.md` | 追踪各模块从规则/模型到章节、模板和产物的完整链路 | 重复、覆盖、矛盾和流程问题清单 |
| `060task_03_理想报告结构与统一渲染整改方案_20260812.md` | 提出理想报告长相、格式、Report IR 和验收标准 | 待确认目标方案与实施顺序 |

## 执行顺序

```text
任务 01：先确认事实和文件职责
    ↓
任务 02：再审核当前生成和拼接问题
    ↓
任务 03：最后确定目标格式和整改方案
    ↓
用户确认目标方案
    ↓
再修改代码和模板
```

## 当前不能直接下的结论

- 共享案例数量增加，不等于案例事实已经审核通过；
- CLI 通过，不等于报告内容符合黄金示例；
- DOCX/PDF 能生成，不等于模板内容合理；
- 章节数量一致，不等于章节职责没有重复；
- 模型输出有内容，不等于结论有证据支持。

## 总体验收口径

每个功能最终都要能回答：

```text
正式需求要求什么？
当前代码在哪一步处理？
当前报告实际生成什么？
是否重复或遗漏？
模板是否改变了含义？
最终产物是否与结构化结论一致？
```

本目录只记录方案和审计结果，不直接存放运行产物。运行产物继续放在 `tmp/` 或 `runs/`，验收结论放在 `status/check/`。
