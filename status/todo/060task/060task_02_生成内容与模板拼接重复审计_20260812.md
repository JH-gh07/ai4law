# 060task 02：生成内容与模板拼接重复审计

> 日期：2026-08-12
> 状态：审计方案与已知风险清单
> 目标：确认每个模块的内容从哪里生成、在哪里拼接、是否重复或覆盖

## 一、统一审计链路

每个功能按以下链路逐步记录：

```text
输入事实
→ Schema 校验
→ 文件解析
→ 确定性事实/规则
→ 法规检索
→ 模型调用
→ 章节对象
→ 模板映射
→ Markdown/DOCX/PDF/JSON
```

每一步必须记录：输入、输出、负责人模块、是否重新生成同一内容、是否改变上一层结论。

## 二、当前代码中已能看到的重复风险

### 1. 每章重复携带完整上下文

多个模块对每个章节分别调用 `generate_chapter()`，每章都收到企业、接收方、数据、风险和法规上下文。若提示词没有明确章节边界，模型会重复生成背景和法律依据。

重点文件：

- `backend/domains/cn/pipia/service.py`
- `backend/domains/eu/bcr_review/service.py`
- `backend/domains/eu/scc_review/service.py`
- `backend/domains/us/cpra/service.py`

### 2. 规则结论和模型结论可能重复判断

正确方式应是：规则先确定“风险/路径/材料状态”，模型只解释和组织语言。当前部分路径是把规则结果和原始事实再次交给模型，让模型重新表达甚至重新判断，存在结论漂移风险。

重点核查：

- 风险等级是否由同一字段提供给所有章节；
- 模型是否能改变 `RED/HIGH/BLOCKED/SUSPEND` 等确定性结论；
- 模型回退后是否保留原规则 findings；
- 章节内容是否覆盖 JSON 结论。

### 3. 章节摘要和详细表格可能重复

`backend/domains/eu/bcr_review/service.py` 同时存在章节摘要、详细 findings table、`_render()` 和 `_render_document_driven()`，是当前最需要优先检查的模块。

需要确认最终产物中是否同时出现：

- 同一问题的摘要；
- 同一问题的详细行；
- 同一问题的整改建议；
- 模板固定文本中的再次说明。

### 4. 模板固定文字和模型文字可能重复

各模块的 `_build_template_mapping()`、`_render()` 和 `*_report_renderer.py` 可能同时写入固定标题、固定法律说明和模型章节。必须对最终 Markdown、DOCX、PDF 做文本抽取比对，不能只看 Python 调用关系。

### 5. 多格式可能不是同源输出

当前存在：

- 公共 Markdown/DOCX/PDF renderer；
- 模块专属 renderer；
- 从 Markdown 生成 PDF 的路径；
- 从模板 mapping 直接生成 DOCX 的路径。

这可能导致 Markdown 和 DOCX/PDF 的章节、表格、脚注和结论不一致。

## 四、需要生成的审计证据

每个模块至少保存：

1. 章节标题和章节内容摘要；
2. 结构化 findings/risks/decision；
3. 模板映射字段；
4. Markdown 纯文本；
5. DOCX/PDF 抽取文本；
6. 重复段落、重复 finding 和结论矛盾列表；
7. 每段内容的来源：规则、用户输入、附件、模型或模板固定文字。

## 五、重复判定标准

不能只按字符串完全相同判断重复，还要检查语义重复：

- 同一 finding ID 在多个章节完整展开；
- 同一风险结论换一种措辞重复出现；
- 同一法律依据连续多次解释但没有新增判断；
- 一个表格和一个段落表达同一问题且都承担主结论；
- 模板固定段落和模型段落表达同一功能。

建议规则：

```text
一个 finding 只能有一个“完整主展示位置”；
其他位置只能显示编号、状态和一句摘要；
一个 decision 只能有一个权威来源；
模型不得重新创建 finding 或改变 decision。
```

## 六、当前审计结论

目前可以确认的是代码存在多条生成和渲染路径，具备重复拼接条件；尚不能仅凭源码断定每个最终产物都已重复。必须完成实际产物抽取和逐段对照后，才能决定删除章节、合并模板还是重构公共渲染层。

### 问题 4：当前去重只能发现完全相同文本

[DedupValidationPass](/Users/oujiazhan/Desktop/实验室/社团/代码/ai4law/backend/common/reporting/compiler/core.py:116) 只对 `reuse_policy == single_use` 的 block 执行：

### 问题 6：EO 14117 产物存在转义和段落结构错误

[EO 14117 Markdown](/Users/oujiazhan/Desktop/实验室/社团/代码/ai4law/tmp/us_14117/markdown.md:1) 当前标题包含字面量 `\u98ce\u9669...`，第 15 行还将章节标题、编号、结论和引用挤在同一行。

根因链路待核实：

```text

→ JSON 或模板层进行转义
→ Markdown renderer 未做一次且仅一次的 Unicode 解码/段落归一化
→ 字面量转义进入最终用户产物
```

此问题必须同时检查 Markdown、DOCX、PDF，避免只修一个格式。

### 问题 7：Diagnosis 和 Review 不能按 Markdown 模块漏审

这两个注册模块没有独立的 `tmp/<module>/markdown.md`，但仍然属于 11 个模块的完整审计范围：

- `diagnosis` 在 [report_renderer.py:451](/Users/oujiazhan/Desktop/实验室/社团/代码/ai4law/backend/domains/cn/transfer_diagnosis/report_renderer.py:451) 先生成 `template_markdown`，随后在 [report_renderer.py:452-468](/Users/oujiazhan/Desktop/实验室/社团/代码/ai4law/backend/domains/cn/transfer_diagnosis/report_renderer.py:452) 把“企业回答、诊断结果、AI 摘要、模板化报告、机器附录”拼成 sections，再输出 HTML/PDF。必须检查模板化报告是否把诊断结果重复写入，以及 HTML 与 PDF 是否一致。
- `review` 在 [service.py:462](/Users/oujiazhan/Desktop/实验室/社团/代码/ai4law/backend/domains/cn/document_review/service.py:462) 生成 sections，随后在 [service.py:470-490](/Users/oujiazhan/Desktop/实验室/社团/代码/ai4law/backend/domains/cn/document_review/service.py:470) 分别生成 DOCX/PDF；上传 DOCX 还可能在 [service.py:492-506](/Users/oujiazhan/Desktop/实验室/社团/代码/ai4law/backend/domains/cn/document_review/service.py:492) 生成带批注版本。必须检查报告中的问题清单、整改路线图和原文批注是否重复或不一致。

因此，审计输出格式不能固定写成“每个模块都必须有 Markdown”，而应记录每个模块的真实格式契约；如果后续决定统一为 Report IR，多格式渲染也必须保留这些模块的 HTML 和批注 DOCX 需求。

## 八、根因验证方法

每个问题必须用以下方式证明：

1. 在 `trace/` 中找到章节生成事件；
2. 保存生成前的 `chapter.title` 和 `chapter.content`；
3. 保存 renderer 接收的 sections 或 template mapping；
4. 抽取最终 Markdown/DOCX/PDF 文本；
5. 标记重复内容首次产生和再次拼接的准确步骤；
6. 修改后用同一 case、同一输入和同一断言复跑。

不能只删除最终 Markdown 中的重复文字；必须修正最早产生重复或错误拼接的职责边界。
