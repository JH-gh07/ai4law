## 三、阶段一：引用跳转横切验收

**目标**：确认 `[n]` 脚注和 `【依据：】` 双路径在所有已接入模块上均可点击、可跳转、失败原因可读。

**范围**：全部 10 模块。已闭环的 6 个仅复验已有报告中的引用，不重新运行。

### 3.1 验收标准

对每个模块的每条引用：

| 检查项 | 路径 A（[n]） | 路径 B（【依据：】） |
|---|---|---|
| 点击弹出 Popover | 条文标题、条文号、法规名 | 同 |
| can_jump=true | 按钮可点击，跳转 /knowledge/laws/:sourceId?article=N | 同 |
| 知识库页面 | URL 含正确 article 参数，页面滚动到指定条文 | 同 |
| prev/next | 上一条/下一条按钮可用 | 同 |
| can_jump=false | 显示中文失败原因 | 同 |
| 待核验/缺少依据 | 不渲染为可点击引用 | 不渲染为链接 |

### 3.2 执行步骤

```bash
# 1. 启动服务
uv run uvicorn backend.main:app --reload --port 8000
cd frontend && npm run dev   # 端口 5174

# 2. 对每个模块：
#   a. 打开 http://127.0.0.1:5174/reports → 找到对应任务
#   b. 逐一点击每个 [n] 脚注，记录：编号、Popover 内容、跳转 URL、条文内容、截图
#   c. 逐一点击每个【依据：...】，重复上述检查
#   d. 记录控制台错误数
```

### 3.3 证据模板（每模块一份）

```markdown
## [模块名] 引用跳转验收

- 任务 ID：[]
- 正文脚注数：N
- 【依据：】块数：M

| 引用 | 路径 | 条文 | can_jump | 跳转 URL | 条文前20字 | 截图 |
|---|---|---|---|---|---|---|
| [1] | A | CN-REG-004 第4条 | true | ...?article=4 | 第四条... | Y |
| 【依据：...】| B | CN-REG-004 第13条 | true | ...?article=13 | 第十三条... | Y |

- 控制台错误：0 / N 个
```

### 3.4 通过/失败判定

| 级别 | 条件 |
|---|---|
| **通过** | 所有引用可跳转或可读失败原因；无 UI 报错、白屏、404 |
| **部分通过** | 存在已知非代码原因（如 PDF 解析缺口致条文缺失）的无法跳转，且逐条列出原因 |
| **失败** | 存在代码原因（字段名错、路由错、API 500）的无法跳转 |
