# 3.2 BCR审核

## 模块目标
对 BCR 文档进行合规完整性与可执行性审核，输出评级与整改建议。

## 知识库要求

### 法规主信源
- GDPR 第47条（BCR）
- EDPB BCR 指南与建议

### 补充信源
- 欧盟监管实践口径
- 审批常见缺陷案例

### 模板资产
- BCR 审查报告模板（摘要/详细问题/优先级）

## 输入规范
字段来源：`doc/v2/schemas/raw/module_input_fields.csv`（`module=3.2`，来源图 `3.2.png`）

| 审查项编码 | 审查模块 | 审查项 | 录入方式 | 必填 | 说明 |
|---|---|---|---|---|---|
| 3.2-C1 | 结构完整性 | EDPB核心章节覆盖检查 | 审查打分 | 是 | 检查是否覆盖约束力、责任、范围、原则、权利、TIA、更新机制 |
| 3.2-C2 | 法律约束力 | 集团内部约束力 | 审查打分 | 是 | 是否通过内部协议对成员实体形成约束 |
| 3.2-C3 | 法律约束力 | 第三方受益人权利 | 审查打分 | 是 | 是否可被数据主体强制执行 |
| 3.2-C4 | 责任与赔偿 | 欧盟责任主体 | 审查打分 | 是 | 是否明确欧盟实体承担责任与赔偿 |
| 3.2-C5 | 数据保护原则 | 合法性基础具体性 | 审查打分 | 是 | 合法基础是否具体可执行 |
| 3.2-C6 | 数据保护原则 | 对外再传输限制 | 审查打分 | 是 | Onward Transfer 限制是否充分 |
| 3.2-C7 | 第三国法律/TIA | 目的地法律风险评估义务 | 审查打分 | 是 | 是否承诺持续评估第三国法律实践 |
| 3.2-C8 | 第三国法律/TIA | 政府访问请求通知义务 | 审查打分 | 是 | 是否规定通知与挑战机制 |
| 3.2-C9 | 可读性与可执行性 | 文本清晰性 | 审查打分 | 是 | 是否存在术语不一致与执行歧义 |
| 3.2-C10 | 可读性与可执行性 | 内部执行机制 | 审查打分 | 是 | 培训、审计、投诉、DPO角色是否明确 |

| 附件 | 格式 | 必填 |
|---|---|---|
| BCR 主文档 | pdf/docx | 是 |
| 组织治理附件 | pdf/docx | 否 |

## 输出规范
| 文件 | 命名规则 | 格式 |
|---|---|---|
| BCR-C 合规审查报告 | `[公司名称]_BCR-C_合规审查报告_[日期].pdf/docx` | pdf/docx |

### 报告结构
- 报告摘要
- 合规评级（基本合规/部分缺失/高风险）
- 详细审查结果
- 风险优先级（高/中/低）

## 功能流程
1. 导入 BCR 主文档并完成结构解析。
2. 按 `3.2-C1~C10` 逐项审查并记录证据。
3. 自动汇总为“基本合规/部分缺失/高风险”评级。
4. 输出高/中/低优先级整改建议与报告。

## 验收标准
- 评级与问题清单一致。
- 高风险项可直接定位与复核。
