**中国模块（2.x）你们要做什么**
1. 2.1 合规路径诊断  
- 做动态问答流程（状态0~4）。  
- 做规则判定与路径分流（安全评估/认证或标准合同）。  
- 产出 `PDF/HTML` 诊断报告，包含“答案摘要+法规依据+判定逻辑+后续行动”。  
- 支持“一键跳转到2.2/2.3并带会话上下文”。

2. 2.2 安全评估路径  
- 做“表单+批量上传”双输入。  
- 覆盖文档列出的申报材料类型（证件、授权书、申报表、合同、风险评估材料）。  
- 生成核心交付物：`数据出境风险自评估报告（草案）.docx`。  
- 支持章节预览 + 打包下载 `zip`。

3. 2.3 认证/标准合同路径  
- 做输入字段schema（当前文档里有留白，需你们补齐成可校验字段）。  
- 生成 `PIPIA` 报告草案 `docx`。  
- 严格按模板样式（四号仿宋/Times New Roman、行距26磅等）。

4. 2.4 通用服务  
- 先拆服务类型：尽调/备忘录/TIA/整改清单。  
- 每种类型定义输入字段与输出模板。  
- 先做最小可运行：docx 输出 + 引用依据。

5. 2.5 文档专项智能审查  
- 按文档要求支持多文件类型输入（合同、隐私政策、内部制度等）。  
- 输出审查报告必须有：定位、原文、问题类型、风险分析、法规依据、修改建议。  
- 按专项文档升级为“双模式”：  
  - 模式A 审查报告版  
  - 模式B 批注/修订版（合同重组+差异说明）

**欧盟模块（3.x）你们要做什么**
1. 3.1 SCC审查  
- 接收SCC文件，走条款级审查。  
- 输出 `SCC合规审查报告.docx`，结构和2.5一致。

2. 3.2 BCR审核  
- 接收BCR材料，做结构化评级（基本合规/部分缺失/高风险）。  
- 输出 `BCR-C` 报告，支持 `pdf/docx` 双格式。  
- 报告要有风险优先级和整改路径。

3. 3.3 DPIA草案生成  
- 把文档里的电子表格输入转成系统schema。  
- 输出 `DPIA docx`（按模板）。

4. 3.4 TIA草案生成 
- 同上，先把输入结构化。 
- 输出 `TIA docx`（按模板）。

**美国模块（4.x）你们要做什么**
1. 4.1 对华数据流动合规  
- 输入至少支持“数据清单+实体清单”。  
- 补齐输出文档定义（文档当前没写死格式，建议固定为docx并可导pdf）。

2. 4.2 加州隐私合规  
- 补齐CPRA输入schema。  
- 输出《加州CPRA合规全景报告》，并固化命名、格式、章节结构。

**“链接”在流程里的具体用途**
1. 官方链接：作为法规依据主信源，进入RAG主库，给报告引用。  
2. 微信/律所链接：作为实务解释与案例补充信源，进入次级知识库，标注“解释性来源”。  
3. 飞书链接：作为内部规则与流程沉淀，转为团队可维护规则包。  
4. 每个模块都要做“来源标注”：输出里区分“法规原文依据”与“实务解释依据”。
