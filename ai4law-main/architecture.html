AI4Law：跨境数据合规“判路 + 生成 + 审查”系统

一句话逻辑：用户在四大功能模块中提交材料，系统先做规则判路，再用 RAG + 生成引擎产出可提交文档，并在报告中心完成下载与引用追溯。

功能模块：CN / EU / US / 公共能力 主方法：规则约束 + RAG 检索 + 模板化生成 输出：md/docx/pdf/xlsx/zip 执行形态：同步 + 异步任务轮询

项目在做什么

把复杂的跨境合规工作，拆成可执行模块（诊断、评估、PIPIA、SCC、DPIA/TIA、CPRA、合同审查）。

通过什么技术实现

Streamlit 前端 + FastAPI 后端 + 规则引擎 + RAG 检索 + 文档渲染工具链 + 异步任务管理。

最终怎么交付

生成可下载报告与附件包，提供法条/案例引用追溯，支持复核、提交与版本留痕。

执行流程

    技术原理

      功能模块分区（业务视角）

      中国大陆 -> 境外（2.1~2.5）

      诊断、评估、PIPIA、通用服务、文档审查。

      欧盟 -> 境外（3.1~3.4）

      SCC/BCR 审查 + DPIA/TIA 草案生成。

      美国 -> 境外（4.1~4.2）

      对华数据流动合规 + CPRA 合规全景。

      公共能力

      模块总览、报告中心、知识库中心、引用联动。

      项目主逻辑（技术执行链路）

      1. 输入采集

      Streamlit 页面 + Schema 表单 + 附件上传。

      2. 接口校验

      FastAPI/Pydantic 校验，422 字段级错误回传。

      3. 规则判路

      decision_tree + 风险评分确定执行分支。

      4. 模块执行

      assessment/scc/pipia/bcr/dpia/tia/cn_flow/cpra。

      5. 证据注入

      RAG 检索法规案例，注入章节/依据。

      6. 文档生成

      LLMAdapter + 模板渲染输出多格式产物。

      7. 发布追溯

      报告中心下载 + 知识库引用匹配与跳转。

      技术栈与依赖（实现视角）

      前端：Streamlit

      多页面模块导航，状态保存，报告预览与下载。

      后端：FastAPI

      `/api/v1` 模块路由，`/api/v0` 任务网关。

      任务：InMemoryTaskManager

      submit/status/retry/cancel + 线程池执行。

      检索：retrieve_regulations

      法域/路径约束检索，支持离题拒答策略。

      渲染：report/artifacts

      markdown/docx/pdf/xlsx/zip 统一导出。

      外部：得理 API（可选）

      配置 appid/secret 时增强案例检索。

      执行原理（为什么这么跑）

      规则先行

      先判路再生成，降低大模型自由发挥导致的偏差。

      RAG 增强

      给生成过程注入法规/案例证据，提升可解释性。

      一致性门禁

      附件角色、路径类型、字段约束自动检查。

      异步稳态

      长任务轮询 + 重试，避免前端长阻塞。

      可追溯输出

      报告引用可定位来源，支持复核与答辩。

      降级可用

      无外部密钥时仍可用本地检索/本地生成链路。

      状态与存储（数据落在哪里）

      storage/uploads

      模块上传文件落盘，供后续解析。

      storage/drafts

      前端草稿保存与恢复。

      outputs/*

      最终报告及打包附件归档。

      knowledge/index

      sources.csv / practice_cases.csv 索引。

      knowledge/normalized

      regulation_articles.jsonl 规范化法规库。

      任务状态（内存）

      TaskSnapshot 当前不持久化，重启清空。
