# D06 区域初赛 - 项目简介

## 1. 项目基础信息

- 项目名称：AI4Law 数据跨境合规工具
- 赛题方向：D06 法律AI应用创新与实践
- 项目类型：法律工具应用 + 系统解决方案
- 一句话定位：将企业非结构化业务材料转化为可直接用于监管申报与内部决策的标准化合规资产。
- 目标用户：
  - 有跨境数据业务的企业（跨国企业、出海企业）
  - 企业法务、合规团队
  - 律师/律所
- 当前阶段范围（P0）：
  - 重点打通“中国大陆 -> 境外”场景
  - 覆盖路径诊断、报告生成、文档审查等核心能力

---

## 2. 项目需求分析

### 2.1 行业痛点

1. 法律流程复杂：企业难以快速判断应走“安全评估 / 标准合同备案 / 认证”哪条路径。
2. 文书产出成本高：风险自评估报告、PIPIA 等文书依赖大量人工，周期长、成本高。
3. 合规审查不可规模化：隐私政策、数据处理协议等文件逐条审查工作量大、一致性不足。
4. 可追溯与可审计要求高：法律场景需要“结论 -> 法规依据 -> 风险等级 -> 人工复核”的完整链路。

### 2.2 目标价值

1. 将“周级人工流程”压缩为“分钟级草案生成”。
2. 用结构化输出与引用链提升一致性和可解释性。
3. 通过风险分级与门控机制降低误判风险，保障法律场景安全边界。

---

## 3. 解决方案思路

项目采用“规则引擎 + LLM + RAG + 结构化中间态”组合方案。

### 3.1 产品结构（五大模块）

1. 合规路径诊断：规则驱动问答，判定应走路径。
2. 安全评估路径：生成《数据出境风险自评估报告》草案。
3. 认证/标准合同路径：生成《个人信息保护影响评估报告（PIPIA）》草案。
4. 通用服务：生成 TIA、尽调报告、合规备忘录、整改清单等。
5. 文档智能审查：对合同/隐私政策等进行条款级审查与修改建议输出。

### 3.2 核心技术路线

1. 四层架构：表现层 -> 应用服务层 -> AI推理层 -> 数据层。
2. 两级编排：腾讯元器（顶层工作流编排） + 自建 Python 执行层（RAG、解析、渲染）。
3. 统一 JSON Schema 中间态：LLM 输出先结构化校验，再渲染 docx/PDF。
4. 引用链与风险门控：每条关键结论必须附法规依据；高风险或低置信度自动标记人工复核。

---

## 4. 关键功能说明

### 4.1 合规路径诊断（规则引擎）

- 功能：通过 5 个核心问题快速判定路径。
- 特点：
  - 采用前端状态机规则，不依赖 LLM 判定。
  - 低延迟、可解释、确定性强。
  - 生成《合规路径诊断报告》并可携带上下文跳转后续模块。

### 4.2 报告生成（安全评估 / SCC）

- 功能：从表单与附件中自动生成规范化报告草案。
- 五步流程：
  1. 材料理解（抽取企业画像）
  2. 法规检索（混合检索 + 重排序）
  3. 逐章节生成（引用链 + 风险标注）
  4. 一致性校验（跨章节校验与复核标记）
  5. 渲染输出（docx/PDF/ZIP）

### 4.3 文档智能审查（条款级）

- 功能：对上传文档执行“条款切分 -> 条款分类 -> 逐条审查 -> 聚合输出”。
- 输出：
  - 条款定位
  - 问题类型
  - 风险等级
  - 法规依据
  - 修改建议

### 4.4 质量保障

1. 三层评测：L1 检索层、L2 抽取层、L3 生成层。
2. Golden Set 回归：变更后自动回归，避免能力退化。
3. 安全边界：不输出最终法律意见，明确“需律师/法务复核”。

## 5. 项目使用场景

### 场景一：企业准备数据出境申报材料

1. 用户完成路径诊断。
2. 系统引导进入对应路径（安全评估或 SCC）。
3. 上传材料并生成报告草案。
4. 法务/律师在线预览、下载、复核后用于正式申报。

### 场景二：企业已有制度与协议合规体检

1. 上传标准合同、隐私政策、数据处理协议等。
2. 系统输出条款级问题清单与整改优先级。
3. 合规团队按风险等级推进整改。

### 场景三：企业内部持续合规运营

1. 复用历史任务上下文与企业画像。
2. 定期生成 TIA、尽调与备忘录。
3. 建立“发现问题 -> 修复 -> 复核”的闭环。

## 6. AI工具使用说明（工作流与 Prompt）

本项目严格使用赛题要求工具链：

1. 腾讯元器：顶层工作流编排（Step1~Step5）
2. 腾讯元宝：LLM 推理（抽取、生成、审查、风险分析）
3. 得理开放平台 API：法规/案例检索补充信源
4. CodeBuddy：开发辅助（代码、调试、文档）
5. 腾讯开悟平台：提交、评审与演示承载
6. 小理AI：法律产品形态与交互参考

### 6.1 工作流示意（以安全评估报告为例）

1. `file_parser`：解析文件，提取文本
2. `profile_extractor`：抽取 `CompanyProfile`
3. `rag_search`：混合检索法规条文与案例
4. `chapter_generator`：逐章生成（含引用链与风险标注）
5. `consistency_checker`：一致性与冲突检查
6. `report_renderer`：渲染输出 docx

### 6.2 Prompt 策略（摘要）

1. 角色约束：限定为法律合规辅助，不给“最终法律意见”。
2. 输出约束：严格按 JSON Schema 输出；字段缺失触发重试。
3. 引用约束：关键结论必须包含法规引用（条文编号、来源）。
4. 风险约束：输出 HIGH/MEDIUM/LOW + 触发依据 + 是否需人工复核。

### 6.3 代表性 Prompt 片段（示例）

#### 示例 A：章节生成 Prompt（摘要版）

```text
你是数据跨境合规报告生成助手。请基于企业画像与检索到的法规片段，
生成“数据出境目的与必要性分析”章节。必须输出为 JSON，
并满足给定 Schema。每个关键结论必须引用至少 1 条法规依据。
若依据不足，请标记 low_confidence 并写明需人工复核原因。
```

#### 示例 B：条款审查 Prompt（摘要版）

```text
你是法律文档条款审查助手。输入为单条条款文本与同类法规要求。
请输出：问题类型、风险等级、法规依据、修改建议。
不得编造法规；若无充分依据，明确标记“需人工复核”。
```

## 附：当前项目边界声明（初赛）

1. 本项目定位为法律合规辅助工具，不替代律师意见。
2. 当前以中国大陆数据出境场景为主（P0），其他法域为后续扩展方向。
3. 所有高风险或低置信度结论均强制门控，要求人工复核。
