# legal-markdown.ts `explodePackedLine()` 误拆行分析

## 涉及文件

[frontend/src/lib/legal-markdown.ts](../../frontend/src/lib/legal-markdown.ts)

## 症状

页面渲染时，类似 `Article 28、记录和DPIA联动` 的文本被错误拆分为：

```
Article 2
8、记录和DPIA联动
```

导致：
- 上一行末尾只剩孤立的 `2`
- 下一行 `8、记录和DPIA联动` 被渲染成 H2 标题（大字号）

这不属于 CSS/样式问题，也不是 Markdown 标题的天然行为，而是`normalizeLegalMarkdown` 的前置规范化阶段将法条号误识别为列表编号并强行拆行。

## 根本原因

`explodePackedLine()`（第 12–22 行）包含四条替换规则，它们看到 `数字+、` 或 `数字+.` 就无条件在前面插入 `\n`，完全不检查数字是否属于法条名称的一部分（如 `Article 28`、`Art.28`、`GDPR Art. 28`、`第28条`）。

## 逐条风险分析

### 规则 1（行 16）：`第X章` 拆分

```ts
.replace(/(?<!\n)(第[一二三四五六七八九十百千万零〇两0-9]+章)/g, "\n$1")
```

| 风险等级 | 说明 |
|----------|------|
| **低** | `第...章` 在中文法律文本中几乎永远是章节标题。正文中出现“参见第三章的规定”，拆开也无害。 |

---

### 规则 2（行 17）：`数字+、` 拆分 — **主犯之一**

```ts
.replace(/(?<!\n)([一二三四五六七八九十百千万零〇两0-9]+、)/g, "\n$1")
```

| 风险等级 | 说明 |
|----------|------|
| **高** | 字符类同时包含中文数字和阿拉伯数字。中文数字 + `、` 几乎永远是段落编号；但阿拉伯数字 + `、` 可以是法条号的一部分。 |

**误判示例：**

| 原文 | 正则匹配 | 拆后结果 | 正确？ |
|------|---------|---------|--------|
| `Article 28、记录...` | `28、` | `Article \n28、记录...` | ❌ |
| `Art. 28、DPIA` | `28、` | `Art. \n28、DPIA` | ❌ |
| `GDPR Art.28、处理...` | `28、` | `GDPR Art.\n28、处理...` | ❌ |
| `一、适用范围` | `一、` | `\n一、适用范围` | ✅ |
| `1、数据最小化` | `1、` | `\n1、数据最小化` | ✅ |

---

### 规则 3（行 18）：全角括号编号

```ts
.replace(/(?<!\n)(（[一二三四五六七八九十百千万零〇两0-9]+）)/g, "\n$1")
```

| 风险等级 | 说明 |
|----------|------|
| **中低** | 全角括号 `（一）` 在法律文本中几乎都是条款编号，但 `参见附件（28）的规定` 会被拆成 `参见附件\n（28）的规定`，附件编号被误判为标题。 |

---

### 规则 4（行 19）：`(数字)` / `数字.` / `数字、` — **主犯之二，最激进**

```ts
.replace(/(?<!\n)(\(?\d+\)|\d+[、.])\s*(?=\S)/g, (_, marker) => `\n${marker} `)
```

| 风险等级 | 说明 |
|----------|------|
| **极高** | 匹配模式极其广泛，几乎所有带数字的上下文都可能被命中。 |

**误判示例：**

| 原文 | 匹配 | 拆后结果 | 正确？ |
|------|-----|---------|--------|
| `Article 28、记录...` | `28、` | `Article \n28、记录...` | ❌ |
| `GDPR Art.28.1 规定` | `28.` | `GDPR Art.\n28. 1 规定` | ❌ |
| `第28条、数据处理` | 不匹配（条≠、.） | — | 侥幸安全 |
| `28.5% 的概率` | `28.` | `\n28. 5% 的概率` | ❌ 小数被拆碎 |
| `Section 3.2.1` | `3.` 或 `1.` | 乱拆 | ❌ |
| `Model-3.0 版本` | `3.` | `Model-\n3. 0 版本` | ❌ |
| `v2.1.0` | `2.` | `v\n2. 1.0` | ❌ |
| `1. 数据最小化` | `1.` | `\n1. 数据最小化` | ✅ |
| `(1) 告知义务` | `(1)` | `\n(1) 告知义务` | ✅ |

---

### 规则 5（`classifyLine` 行 29）：中文编号→二级标题

```ts
if (/^[一二三四五六七八九十百千万零〇两0-9]+、/.test(line)) return `## ${line}`;
```

| 风险等级 | 说明 |
|----------|------|
| **中** | 如果上游拆分已把 `28、...` 拆到行首，这里会被升级为 `<h2>`，把法条号渲染成大标题。 |

---

### 规则 6（`classifyLine` 行 30）：全角括号→三级标题

```ts
if (/^（[一二三四五六七八九十百千万零〇两0-9]+）/.test(line)) return `### ${line}`;
```

| 风险等级 | 说明 |
|----------|------|
| **低** | 前提是上游拆分正确。如果 `（28）` 被错误拆至行首，会被升级为 `<h3>`。 |

---

### 规则 7（`classifyLine` 行 31–37）：有序列表匹配

```ts
const ordered = line.match(/^(?:\(?(\d+)\)|(\d+)[、.])\s*(.*)$/);
return `${no}. ${content}`.trim();
```

| 风险等级 | 说明 |
|----------|------|
| **中** | 如果 `28、...` 到达此处，会被格式化为有序列表 `28. ...`，虽不产生标题但格式化仍不正确。 |

---

## 受影响场景汇总

| 场景 | 遭误拆的示例 |
|------|------------|
| `Article + 数字` | `Article 28、...` → `Article \n28、...` |
| `Art. + 数字` | `Art. 28、...` 或 `Art.28、...` |
| `Art + 数字` | `Art 28、...` |
| `Section + 数字` | `Section 3.2.1` → 多处被拆 |
| `Sec. + 数字` | `Sec. 28.1` → `Sec. \n28. 1` |
| `§ + 数字` | `§3.2` |
| `第 + 数字 + 条` | `第28条、` → 本条侥幸安全（`条`≠`、`.`），但仍应预防 |
| 小数 | `28.5%` → `\n28. 5%` |
| 版本号 | `v2.1.0` → `v\n2. 1.0` |

## 修复方案

### 核心原则

**宁愿少拆一个真标题，也绝不能错拆一个法条号。**

### 具体措施

#### 1. 新增辅助函数 `isLegalArticlePrefix()`

检测数字前缀是否为法条引用关键词，拒绝在此类上下文前插入换行：

```ts
function isLegalArticlePrefix(textBefore: string): boolean {
  return /(?:Article|Art\.?|Art|Section|Sec\.?|Sec|§|Regulation|Directive|GDPR|CPRA|SCC|BCR|DPIA|TIA|第\d{0,3})\s*$/i.test(textBefore);
}
```

#### 2. 重构 `explodePackedLine()`

将拆分规则分为安全组（无条件拆分）和需检查组（需通过法条上下文检测）：

- **安全拆分**（无条件）：
  - `第...章`
  - 纯中文数字 + `、`（一、二、三）
  - 全角括号中文数字 `（一）（二）`
  - `【依据：...】`

- **需检查的拆分**（仅当前面不是法条引用时才拆分）：
  - 阿拉伯数字 + `、`
  - `(数字)` / `数字.)` → 同时排除小数和版本号模式

#### 3. 防御性改进 `classifyLine`

将中文数字 + `、` 的 h2 映射与阿拉伯数字 + `、` 分开处理。阿拉伯数字 + `、` 的行首不应自动升级为 h2，只可能是有序列表。

---

## 修复后的 `explodePackedLine()` 逻辑

```
对于每一行：
  1. 先拆【依据：...】
  2. 如果该行已经是 markdown 结构化行（# | - | 1. | > | |），跳过后续拆分
  3. 无条件拆分（安全规则）：
     - 第X章
     - 纯中文数字 + 、
     - 纯中文数字的全角括号
  4. 条件拆分（需法条上下文检查）：
     - 阿拉伯数字 + 、 → 仅当前面不是 isLegalArticlePrefix 时拆分
     - (数字) / 数字. → 排除小数(数字.数字)、版本号上下文、法条上下文
```
