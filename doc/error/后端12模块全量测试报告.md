## 二、各模块输入输出详细说明

### 2.1 diagnosis — 合规路径诊断 ✅

**输入（前端表单会问的 8 个问题）：**
- `q1_is_ciio`: 是否关键信息基础设施运营者
- `q2_has_important_data`: 拟出境数据是否包含重要数据
- `q3_pii_count`: 自当年起累计拟出境个人信息数量
- `q4_spi_count`: 敏感个人信息数量
- `q5_no_personal_info`: 是否完全不涉及个人信息
- `q6_scenario`: 法定豁免情形（contract_performance / hr_management / 等）
- `q7_receiver_type`: 境外接收方类型
- `q8_purpose`: 出境目的描述

**输出结构：**
```
report_path         → 报告文件路径
html_report_path    → HTML 报告路径
pdf_report_path     → PDF 报告路径
output_files        → 输出文件映射
result.risk_level   → 风险等级
result.path_result  → 合规路径判断结果
```

**与 Spec 预期一致：** ✅
Spec 描述：用户通过表单回答封闭式问题 → 系统按决策树返回合规路径（安全评估/标准合同/认证/豁免）。输出包含路径判断结论。

### 2.2 pipia — 个人信息保护影响评估（PIPIA） ✅

**输入（五大模块）：**
- `route_type`: 申报路径（scc_filing / certification / assessment）
- `company_profile`: 企业基本信息（名称/信用代码/CIIO/处理量/行业）
- `transfer_context`: 出境背景（目的/接收方/国家/法律依据）
- `personal_info_scope`: 个人信息范围（类别/敏感类别/数量）
- `rights_protection`: 权利保障（告知/同意/DSAR通道/保留政策）
- `emergency_plan`: 应急预案
- `attachments`: 至少 1 个 SCC 合同附件

**输出结构：**
```
report_path         → 报告路径
output_files        → 输出文件（.docx / .md / .zip）
route_type          → 申报路径
risk_level          → 风险等级（high / medium / low）
chapters            → 报告章节（各章节标题+正文）
consistency_issues  → 一致性问题清单
facts               → 提取的事实信息
```

**与 Spec 预期一致：** ✅
Spec 中"认证/标准合同路径"功能说明：用户输入表单 → 系统生成 PIPIA 报告（草案）。输出包含结构化章节、风险项、一致性检查结果。完全一致。

## 三、失败模块诊断

### 3.1 assessment (cn_assessment) — HTTP 500

**症状：** POST /api/v1/assessment/generate → 303 秒后返回 Internal Server Error
**根因推测：** 安全评估申报需要调用得理 API 或 LLM 进行深度检索和报告生成，后端代码在某处抛了未捕获异常。
**Payload 已验证正确：** 422 已全部修复，500 是代码逻辑错误。
**后续：** 需要检查后端 `backend/modules/assessment/service.py` 日志定位异常。

### 3.2 scc (cn_scc) — HTTP 500

**症状：** POST /api/v1/scc/generate → 立即返回 Internal Server Error
**根因推测：** 该端点可能存在路由注册问题，或与其他模块冲突（"scc" vs "eu_scc"）。
**Payload 已验证正确：** 枚举值 receiver_type="third_party_processor" 等均按 Schema 要求。
**后续：** 检查 `backend/modules/scc/router.py` 和 `backend/api/router.py` 确认路由注册。

### 3.3 dpia (eu_dpia) — HTTP 500

**症状：** POST /api/v1/dpia/generate → 210 秒后返回 Internal Server Error
**根因推测：** DPIA 草案生成需要调用 LLM 进行多步骤生成（必要性论证/风险评估/缓解措施），某步失败。
**Payload 已验证正确：** 所有 min_length=2 的字符串字段均已满足。
**后续：** 需要看 `backend/modules/dpia/service.py` 日志。

### 3.4 cn_flow — HTTP 500

**症状：** POST /api/v1/cn-flow/generate → 立即返回 Internal Server Error
**根因推测：** 该模块可能是新模块，LLM client 未被正确注入。
**Payload 已验证正确：** attachments 含 2 项等要求均满足。
**后续：** 检查 `backend/modules/cn_flow/router.py` 中 service 初始化。

### 3.5 cpra — 超时

**症状：** POST /api/v1/cpra/generate → 300 秒超时
**根因推测：** CPRA 合规需要大量 LLM 调用（5+ agents 并行），可能卡在某个 API 调用上。
**Payload 已验证正确：** 所有字段已满足 Schema 要求。
**后续：** 增加超时到 600s 重试，或检查 LLM provider 是否可达。

### 3.6 review — SKIP

**症状：** review 需要 `uploaded_files` 字段指向真实的上传文件路径。测试脚本中提供的路径不存在。
**正确调用方式：** 先通过 `POST /api/v1/v0/files/upload` (multipart/form-data) 上传 .docx 文件，获取 file_id/path，再将路径传入 `uploaded_files`。
**后续：** 需要文件上传功能，或后端提供跳过文件检查的测试模式。
