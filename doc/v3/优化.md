下面是一份**可落地的改进建议**（按优先级，含改动点）：

**P0 立刻修（影响最大）**
1. **强制输入对齐（禁止编造）**  
- 做法：在 `backend/common/llm/module_generator.py` 或各模块 `generate_chapter` 前加入约束提示：仅允许引用输入字段+RAG命中文本；超出内容必须标注“推测/建议”。  
- 预期：减少“跨境电商/EEA”等幻觉场景。

2. **结论与规则分离（LLM 不得覆盖规则结论）**  
- 做法：关键结论（风险等级、红黄绿）只由规则输出，LLM 仅解释。  
- 改动点：`backend/modules/cn_flow/service.py` 的 `risk_rating` 组装逻辑（高风险实体仅 `is_restricted_party=True`）。

3. **标题与文件名一致**  
- 做法：模板标题统一加入“草案”，保持与文件名一致。  
- 改动点：模板 `.md/.docx` 标题行，或渲染前注入统一标题。

**P1 快速提升质量（1-2天内可做）**
4. **RAG 查询改写（CN 优化）**  
- 做法：在 `backend/common/rag/retriever.py` 前加 query rewrite：中文关键词 + 明确法规名。  
- 例如：`"个人信息出境标准合同办法 第×条 PIPIA"`、`"数据出境安全评估办法 第×条"`  
- 预期：CN 命中率提升，降低编造。

5. **引用链输出（每段至少1条）**  
- 做法：在章节生成时附 `citations`，输出到模板对应字段中；若无命中则输出“未检索到依据”。  
- 改动点：各模块 `report_renderer` / `_build_template_mapping`。

6. **一致性校验与告警**  
- 做法：生成后跑对齐检查（行业、接收方、规模、路径），不一致时插入“告警段”。  
- 改动点：各模块 `generate_report` 后增加校验函数。

**P2 中期优化（1-2周）**
7. **RAG 语料补齐（CN 专项）**  
- 做法：补齐“标准合同办法/PIPIA/安全评估办法”等专属条文，按路径标注 `path=assessment/scc`.  
- 改动点：`doc/knowledge/normalized/regulation_articles.jsonl` 与 ingestion 脚本。

8. **证据覆盖率指标**  
- 做法：统计报告内“有引用的段落比例”，低于阈值输出“证据不足”。  
- 让用户可量化判断“可信度”。
