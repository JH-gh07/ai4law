---



# 一、路径层



路径层解决的问题是：



```Plain Text
企业当前场景到底适用哪类合规要求？
是否应当进入某个具体业务模块？
```



路径层目前包括：



```Plain Text
1. 中国路径诊断 diagnosis report
2. 美国 EO14117 对华数据流动适用性判断
3. 欧洲路径判断，暂时待设计
```



路径层的处理逻辑是：



```Plain Text
用户输入业务情况
→ 系统按规则判断是否命中
→ 检查法规依据是否存在
→ AI 做一致性复核
→ 输出路径适用性报告
```



这里的主判断必须来自规则，不由 AI 直接决定。



AI 的作用是复核：



```Plain Text
规则结论是否和用户事实矛盾；
是否存在缺失信息；
是否存在过度判断；
报告表达是否稳妥。
```



路径层最后输出：



```Plain Text
推荐路径
命中规则
未命中规则
缺失事实
法规依据
一致性复核结果
下一步建议
```

# 二、功能层



功能层分三类：



```Plain Text
1. 合同审查类
2. 填表格类
3. 草案模板生成类
```



---



## 1\. 合同审查类



包含：



```Plain Text
review
SCC
BCR
```



合同审查类解决的问题是：



```Plain Text
企业已经有合同、协议、制度或条款文本，
系统帮助企业判断原文哪里有问题、为什么有问题、应该怎么改。
```



业务流程是：



```Plain Text
用户上传合同或条款文本
→ 系统读取原文
→ 拆分成可审查条款
→ 判断每条条款属于什么类型
→ 匹配 GDPR / SCC / BCR / 数据保护法规依据
→ 审查每条条款是否合理、模糊、缺失或不合规
→ 生成风险等级和修改建议
→ 输出审查报告或批注版文件
```



它要回答的问题是：



```Plain Text
哪里写得不清楚？
哪里义务不完整？
哪里可能不合法？
哪里需要补充？
应该怎么改？
依据是什么？
```



输出形式包括：



```Plain Text
原文定位
问题类型
风险等级
修改建议
法规依据
审查报告
批注版 / 对照版
```



一句话：



```Plain Text
合同审查类 = 审已有文本，给修改建议。
```



---



## 2\. 填表格类



包含：



```Plain Text
CPRA
```



填表格类解决的问题是：



```Plain Text
企业用自然语言或问卷描述业务情况，
系统把这些信息转换成一张合规差距表或整改清单。
```



业务流程是：



```Plain Text
用户填写企业数据处理情况
→ 系统识别涉及哪些 CPRA 义务
→ 判断每项义务是否满足
→ 生成 gap_items 差距项
→ 给每个差距项风险等级
→ 生成整改建议
→ 输出 Excel 表格和可选摘要报告
```



它要回答的问题是：



```Plain Text
企业有哪些 CPRA 义务？
哪些已经满足？
哪些没有满足？
缺什么材料或机制？
风险等级是多少？
下一步怎么整改？
```



输出形式包括：



```Plain Text
CPRA 义务清单
差距项
风险等级
整改建议
Excel 表格
摘要报告
```



一句话：



```Plain Text
填表格类 = 用户描述进来，合规清单出去。
```



---



## 3\. 草案模板生成类



包含：



```Plain Text
assessment
PIPIA
DPIA
TIA
CN Flow
```



草案模板生成类解决的问题是：



```Plain Text
企业没有完整文书，
系统根据用户输入和固定模板，生成合规文书草案。
```



业务流程是：



```Plain Text
用户填写业务事实和上传材料
→ 系统整理企业事实
→ 检索法规依据
→ 识别风险和问题
→ 组装证据链
→ 形成生成上下文包
→ AI 按固定模板生成章节正文
→ 系统做一致性检查
→ 输出正式草案文件
```



它要回答的问题是：



```Plain Text
这份文书应该怎么写？
哪些事实可以写？
哪些地方证据不足？
哪些表述需要保守？
哪些地方有风险？
哪些整改建议应当放进报告？
```



这里 AI 基于系统整理好的依据写：



```Plain Text
企业事实
风险问题
法规依据
证据链
模板章节
```



输出形式包括：



```Plain Text
docx 文书草案
markdown 预览
pdf
xlsx 风险清单
zip 输出包
中间产物 JSON
trace 留痕
```



一句话：



```Plain Text
草案模板生成类 = 用户输入业务事实，系统按模板生成文书。
```

# 三、引用展示



所有路径层和功能层都要逐步支持引用展示。



目标是：



```Plain Text
报告正文中的法规引用可以悬停查看来源，
点击后查看原文或来源卡片。
```



展示形式包括：



```Plain Text
行内引用
citation popover
source preview card
```



它的作用是：



```Plain Text
让用户知道每个判断依据来自哪里；
让报告结论可以追溯；
减少 AI 编造法规依据的风险。
```



---



# 四、整体



```Plain Text
路径先判断，
再按任务类型进入合同审查、表格清单或草案模板生成，
所有结论都要有规则、事实、法规依据和可追溯引用支撑。
```
