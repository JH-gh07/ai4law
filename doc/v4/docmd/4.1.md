# 4.1 14117行政令合规模块

## 输入项—对应模板—采集方式—输出内容—系统处理逻辑说明

结合原文，4.1 模块的输入并不是泛泛的“上传一些材料”，而是围绕两类核心底稿展开：**数据清单**与**实体清单**。前者用于识别“传什么”，后者用于识别“传给谁”。系统再基于二者的交叉匹配，输出《14117行政令风险评估结论报告》，并给出红灯/黄灯/绿灯结论、高风险实体清单、敏感数据分布、风险匹配矩阵及合规措施建议。

------

## 一、输入项一：出境数据清单（核心）

### 1. 输入项定位

该输入项对应 14117 行政令合规模块中的**核心事实底稿**，用于识别企业计划向境外传输的数据是否属于受重点规制的数据类型，尤其是是否构成：

- 批量敏感个人数据
- 美国政府相关数据

它不是普通的数据资产台账，而是风险评估的基础材料。没有这张清单，系统无法判断某项传输是否触发禁止性或限制性规则。

------

### 2. 对应模板/报告章节

该输入项在报告中主要对应以下分析内容：

#### 对应《报告》中的输入基础部分

- 数据识别与分类基础信息
- 拟出境数据范围与场景说明
- 敏感数据分布分析基础

#### 对应《报告》中的输出分析部分

- **风险详情与分析—敏感数据分布**
- **风险详情与分析—风险匹配矩阵**
- **总体结论与传输可行性判断**

如果你要把它映射成“文档里的采集模板”，可以写成：

> 用于支撑报告中“拟出境数据识别”“重点数据分类”“数据规模与体量评估”“高风险传输路径识别”等章节的事实基础材料。

------

### 3. 采集方式

建议采用 **Excel 上传 + 在线表格补录** 的双轨方式：

#### 方式一：Excel/CSV 批量上传

适合已有数据资产台账、系统字段表、数据目录表的企业。
系统支持上传 `.xlsx / .csv` 文件后自动解析字段，并引导用户完成字段映射。

#### 方式二：在线表格逐条填写

适合数据量较小、尚未形成正式台账、或仅需补充部分高风险数据项的场景。
前端按“单条数据项”逐项录入，支持保存草稿、多人协同补录。

#### 方式三：系统解析后人工确认

对于企业上传的制度文件、接口文档、数据字典、数据库字段导出表，系统可先做初步抽取，再由用户在界面中确认“是否属于重点数据”“是否拟出境”“对应哪个接收方”。

------

### 4. 具体采集内容

这部分不能只写“收集数据项名称”，而要明确每一列为什么收、收完做什么。

建议将“出境数据清单”设计为一张标准化清单表，至少包含以下字段：

#### （1）数据识别字段

用于回答“这是什么数据”。

- 数据项名称
- 数据类别/标签
- 内容描述
- 所属业务场景
- 所属系统/数据库/模块
- 所属业务部门
- 是否拟出境
- 出境场景说明

#### （2）法律定性字段

用于回答“这类数据是否落入 14117 管控范围”。

- 是否涉及美国个人
- 是否可识别到具体个人
- 是否属于个人敏感信息
- 是否属于 14117 所称批量敏感个人数据
- 若属于，具体属于哪一类
  例如：健康数据、生物特征数据、基因组数据、精确地理位置数据、财务数据、特定个人标识符
- 是否属于美国政府相关数据
- 若属于，具体涉及何类对象
  例如：联邦雇员、军方人员、政府承包商、敏感政府设施位置等

#### （3）规模与体量字段

用于回答“风险有多大”。

- 涉及数据主体数量
- 涉及美国人数量
- 当前存量规模
- 计划出境体量
- 出境频率（一次性/定期/持续同步）
- 是否达到“批量”门槛
- 是否长期、持续、自动化传输

#### （4）必要性与替代性字段

用于回答“为什么一定要传、能不能少传”。

- 出境目的
- 出境必要性说明
- 是否可通过脱敏/匿名化/汇总替代
- 是否已最小化
- 是否存在非出境替代方案

#### （5）关联字段

用于和实体清单、传输路径匹配。

- 对应接收方名称/实体 ID
- 对应项目/合同/服务关系
- 对应数据流编号
- 备注

------

### 5. 格式要求

相比原表里“表头必须包含什么”，方案文档里应写得更明确一些：

#### 表单/模板格式要求

出境数据清单应采用标准化表格格式，支持 `.xlsx`、`.csv` 在线导入或页面直接录入。
每一行代表一类拟出境数据项或一组同质数据集合，不建议把完全不同来源、不同接收方、不同用途的数据混在同一行填写。

#### 字段填写要求

- **数据项名称**：应使用企业内部实际字段名、数据集名或业务命名，避免只写“用户信息”“订单信息”这类过泛表述。
- **内容描述**：应写明该数据实际包含的核心内容，而不是仅重复字段名。
- **所属业务场景**：应能对应到具体业务活动，如客服支持、海外云存储、模型训练、财务结算、跨境协同办公等。
- **是否属于重点数据**：由系统初判，用户复核确认。
- **出境必要性说明**：必须写明为什么该数据需要被境外实体访问、调取、下载或接收。
- **接收方关联**：每项数据需尽量绑定到具体接收方，而不是只写“境外关联公司”这种模糊表述。

------

### 6. 系统处理逻辑

这一部分是你最想要的，不只是“收什么”，而是“系统拿来怎么用”。

系统接收出境数据清单后，将按以下顺序处理：

#### 第一步：字段标准化

对上传表格中的字段名、数据类型、数据描述进行归一化处理，将企业自定义字段映射到系统内部统一分类框架。

#### 第二步：重点数据初筛

基于 14117 行政令的重点数据类型，对每一项数据进行规则识别，初步判断其是否可能属于：

- 批量敏感个人数据
- 美国政府相关数据

#### 第三步：规模判断

结合数据主体数量、美国人数量、出境频率、当前存量和拟出境体量，识别其是否达到“批量”或高风险阈值。

#### 第四步：风险标签生成

系统为每条数据生成结构化标签，例如：

- 低风险普通数据
- 敏感个人数据
- 14117重点敏感数据
- 美国政府相关数据
- 高规模持续出境数据

#### 第五步：与实体清单关联

将每条数据与对应接收方绑定，为后续形成“高风险实体—高风险数据”的风险匹配矩阵做准备。

------

### 7. 输出内容

该输入项经过系统处理后，不直接生成一份独立报告，而是形成以下中间成果，并进入总报告：

- 数据分类与标签结果表
- 敏感数据分布统计表
- 高风险数据项清单
- 拟出境重点数据摘要
- 风险匹配矩阵中的“数据侧基础信息”
- 最终报告中的“敏感数据分布”章节内容

------

## 二、输入项二：实体清单输入

实体清单的作用不是简单收一个合作方名单，而是为了识别：**接收方是否属于“被覆盖的人”或与“关注国”存在高风险关联。** 原文已经强调，14117 的难点之一就在于接收方身份识别并不只看注册地，而要看控股、控制、管辖、法律义务等穿透关系。

------

## 三、子项 2.1：外部实体清单

### 1. 输入项定位

该子项用于识别所有可能接收、访问、调取、下载或处理拟出境数据的**外部实体**，包括但不限于：

- 境外关联公司
- 境外客户
- 境外供应商
- 境外云服务商
- 境外外包商
- 境外承包商
- 其他第三方合作机构

它的核心目的，是支撑系统判断某接收方是否可能属于：

- 关注国相关主体
- 被覆盖的人
- 低风险普通接收方

------

### 2. 对应模板/报告章节

该输入项在报告中主要对应：

- **风险详情与分析—高风险实体清单**
- **总体结论与传输可行性**
- **风险匹配矩阵**
- **合规措施建议与行动清单**

可以在方案文档中表述为：

> 用于形成接收方风险画像，支撑报告中“高风险实体识别”“被覆盖的人判定依据说明”“高风险传输路径识别”等章节。

------

### 3. 采集方式

建议采用 **文件上传为主、在线逐条补录为辅** 的方式。

#### 文件上传

支持 `.csv / .xlsx` 批量导入，适合从供应商名录、客户主数据、关联公司清单、合同台账中直接整理上传。

#### 在线补录

适合少量高风险主体逐条新增，尤其适合后期人工补充穿透关系、控股说明、法律管辖说明等复杂字段。

#### 辅助材料上传

可允许企业上传：

- 股权结构图
- 组织架构图
- 合同摘要
- 尽调报告
- 公司官网截图或公开工商资料
  用于支撑系统或人工复核“被覆盖的人”判定。

------

### 4. 具体采集内容

相比原图里的“实体全称、注册国家/地区、统一社会信用代码/税号、股权结构说明”，更适合方案文档的写法应是：

#### （1）实体基础识别字段

- 实体全称
- 实体别名/英文名
- 实体类型
- 注册国家/地区
- 主要经营地
- 税号/统一社会信用代码/注册编号
- 官网或公开信息来源（可选）

#### （2）关系识别字段

- 与本企业关系
  （关联公司/供应商/客户/承包商/云服务商/顾问等）
- 是否直接接收数据
- 是否可访问、调取、下载数据
- 是否存在再转移/再共享

#### （3）控制与穿透字段

- 母公司名称
- 最终受益所有人
- 控股股东
- 实际控制人
- 股权结构说明
- 是否受关注国实体直接或间接控股/控制
- 是否受关注国法律或监管机制约束

#### （4）法律风险判断字段

- 是否可能属于被覆盖的人
- 初步判定依据
- 是否需要进一步人工复核
- 风险等级备注

#### （5）关联字段

- 关联数据项/数据集 ID
- 对应业务场景
- 对应合同/项目编号
- 备注

------

### 5. 格式要求

实体清单应采用一行一实体的结构化清单格式。
对于同一企业集团下不同接收主体，应分别列示，不能只填集团名称后统一概括。
涉及股权结构、受控关系、法律管辖等复杂信息时，应允许在“说明”字段中补充文字，必要时上传附件支撑。

------

### 6. 系统处理逻辑

系统接收外部实体清单后，按以下逻辑处理：

#### 第一步：实体标准化

统一名称格式，识别重复主体、母子公司关系、别名与英文名映射。

#### 第二步：关联识别

识别该主体在数据流中的角色，是直接接收方、访问方，还是间接参与方。

#### 第三步：高风险规则筛查

基于注册地、控制关系、股权结构说明、法律管辖信息，对实体进行初步规则匹配，识别其是否可能与关注国相关，是否可能构成“被覆盖的人”。

#### 第四步：形成实体风险画像

输出实体级风险标签，如：

- 普通境外实体
- 高关注关联实体
- 疑似被覆盖的人
- 需人工复核实体

#### 第五步：进入交叉匹配

将高风险实体与数据清单中的重点数据进行匹配，形成具体传输路径风险。

------

### 7. 输出内容

该输入项经处理后，形成：

- 实体风险画像表
- 疑似“被覆盖的人”清单
- 高风险实体清单
- 风险匹配矩阵中的“实体侧基础信息”
- 最终报告中的“高风险实体清单”章节内容

------

## 四、子项 2.2：内部员工清单（如适用）

### 1. 输入项定位

这部分不是所有企业都必须提供，但一旦业务场景涉及内部员工、内部承包人员、驻外团队、跨境协同访问主体，就需要采集。
原图里已经提示，这一项主要用于筛查“**被覆盖的人**”，即内部是否存在属于高风险身份范围、且可能接触拟出境数据的人员。你给的表里写得很清楚：用于筛查“被覆盖的人”，需包含员工姓名、国籍、所属部门、岗位。

所以它不是一般人事档案，而是用于判断：**企业内部是否存在高风险人员接触链路。**

------

### 2. 对应模板/报告章节

该输入项主要对应：

- 高风险访问主体识别
- 高风险实体/人员补充说明
- 风险匹配矩阵中的访问主体校验
- 合规措施建议中的“访问控制与权限限制”部分

------

### 3. 采集方式

建议采用 `.csv / .xlsx` 文件上传方式，不建议大量在线手填。
原因很简单：这类名单往往来自 HR、IT 权限系统、项目成员表，直接导入更可控。

如涉及隐私保护，可只上传最小必要字段，并允许对员工编号替代姓名做脱敏展示。

------

### 4. 具体采集内容

建议字段包括：

- 员工姓名/员工编号
- 国籍
- 常驻国家/地区
- 所属部门
- 岗位
- 是否接触拟出境数据
- 是否具有下载/导出/管理权限
- 是否驻外/外派
- 是否受关注国法律或居住地因素影响
- 所属项目/系统
- 备注

------

### 5. 系统处理逻辑

系统对内部员工清单的处理重点不在商业尽调，而在访问风险控制：

#### 第一步：识别是否存在高风险接触主体

判断哪些人员可能属于高风险身份范围，或处于高风险司法辖区。

#### 第二步：识别权限范围

看这些人员是否拥有访问、调取、下载、导出拟出境数据的能力。

#### 第三步：与数据流/实体流合并分析

如果某高风险人员同时参与高风险接收方或高风险数据链路，系统将提高整体风险等级。

------

### 6. 输出内容

该子项主要输出为：

- 高风险内部访问主体清单
- 高风险岗位/部门提示
- 对最终结论中“需采取安全措施”的补充依据
- 后续整改建议中的访问控制、权限收缩、人员隔离建议

------

# 五、整合后的系统输出逻辑

把上面三块输入放在一起后，系统不是分别给三份结果，而是统一汇总进 **《14117行政令风险评估结论报告》**。原文已经明确，这份报告至少包括以下三大部分：

## 1. 总体结论与传输可行性

首页直接输出：

- 红灯：禁止传输
- 黄灯：需采取安全措施
- 绿灯：低风险放行

## 2. 风险详情与分析

基于前述输入处理结果，生成：

- 高风险实体清单
- 敏感数据分布
- 风险匹配矩阵

## 3. 合规措施建议与行动清单

基于发现的问题，输出：

- 应停止的传输
- 应整改的路径
- 应补充的控制措施
- 应进一步人工复核的主体或数据链路

------

# 六、可以直接放进方案文档的一版简洁表述

你如果想直接塞进正文，我建议用下面这版：

## 4.1.1 输入项说明

14117 行政令合规模块的输入围绕“传什么”和“传给谁”两条主线展开。系统需至少收集三类基础材料：一是**出境数据清单**，用于识别拟向境外传输的数据是否属于批量敏感个人数据或美国政府相关数据，并记录其类别、规模、业务场景、必要性及对应接收方；二是**外部实体清单**，用于识别境外接收方是否属于关注国相关主体或“被覆盖的人”，并记录其注册地、控制关系、法律管辖、与本企业关系及对应数据流；三是**内部员工清单（如适用）**，用于识别企业内部是否存在高风险访问主体及其权限范围。

## 4.1.2 采集方式说明

系统支持 Excel/CSV 批量上传与在线表格补录两种方式。对数据清单，优先支持数据资产台账、字段目录表、系统清单导入；对实体清单，优先支持供应商名录、客户清单、关联公司清单导入；对内部员工清单，优先支持 HR 或权限系统名单导入。系统在导入后自动完成字段标准化、分类映射和规则初筛，并将需人工确认的项标记出来，供用户补充和复核。

## 4.1.3 系统处理逻辑说明

系统首先对出境数据清单进行标准化和重点数据识别，判断各数据项是否属于批量敏感个人数据或美国政府相关数据；随后对实体清单进行实体标准化与风险穿透分析，识别高风险接收方及疑似“被覆盖的人”；如提供内部员工清单，则进一步识别高风险访问主体及其权限范围。完成单项识别后，系统将高风险实体、高风险人员与重点数据进行交叉匹配，形成具体的高风险传输路径，并据此生成红灯、黄灯、绿灯结论及配套的风险说明和整改建议。

## 4.1.4 输出内容说明

系统最终输出《14117行政令风险评估结论报告》，格式为 PDF/HTML。报告首页给出总体结论与传输可行性判断；正文包括高风险实体清单、敏感数据分布、风险匹配矩阵，以及合规措施建议与行动清单。红灯表示存在明确禁止的交易场景，黄灯表示需补充特定安全措施后方可推进，绿灯表示当前未触发 14117 行政令的直接限制。
