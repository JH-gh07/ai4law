《产品方案 / 系统说明》
一、产品概述
1.1 产品名称

数规通——AI驱动的数据跨境合规诊断与文书智能生成平台。

1.2 产品定位

数规通面向存在跨境数据流动需求的企业、律师/律所及相关服务机构，提供围绕数据跨境合规的一体化辅助能力，包括：

合规路径诊断
合规文书起草
合规材料审查
风险整改建议

产品目标不是替代律师或正式法律意见，而是通过规则引擎 + 知识库检索 + 大模型生成的方式，提升跨境合规工作的效率、标准化程度和可复用性。

1.3 目标用户

本产品当前主要面向三类用户：

企业法务 / 合规负责人
需要快速识别数据跨境场景适用规则，并准备申报或备案材料。
外部律师 / 律所团队
需要高效生成初版合规报告、审查合同及隐私政策、形成风险清单。
出海企业 / 跨国企业业务团队
需要对中国、欧盟、美国等不同法域的数据出境要求建立统一理解和操作流程。
二、建设背景与痛点
2.1 行业背景

随着中国、欧盟、美国等主要法域对数据出境、个人信息保护、敏感数据访问的监管持续加强，企业在开展跨境数据处理活动时，面临的合规要求显著上升。
现有合规工作往往依赖人工完成，存在法律依据分散、材料准备繁琐、判断口径不统一、跨法域难以复用等问题。

2.2 核心痛点

当前数据跨境合规工作主要存在以下问题：

（1）路径判断难

企业往往无法快速判断：
自己究竟应走安全评估、标准合同、认证、SCC、BCR，还是需要进一步做 DPIA/TIA。

（2）材料准备重

安全评估报告、PIPIA、DPIA、TIA、隐私政策、合同附件等文书具有较强模板性，但人工撰写耗时长、成本高、重复劳动多。

（3）已有文件难审查

企业通常已有合同、隐私政策、数据处理协议或内部制度，但难以快速识别其中的缺失条款、风险点和不一致之处。

（4）整改难落地

即使识别出风险，也常缺少结构化、可执行的整改建议与优先级路线图。

三、产品目标

本产品的核心目标是构建一个面向跨境数据合规场景的智能辅助工作台，实现以下能力：

快速判断适用路径
通过结构化问卷、规则判断和法律知识检索，帮助用户识别适用法域与义务路径。
自动生成合规文书草案
面向典型场景自动生成合规报告和评估文书，提高起草效率。
对既有文件进行智能审查
对合同、政策和规则文本进行问题识别与结构化输出。
形成统一整改方案
将诊断、起草与审查结果沉淀为整改清单和后续行动建议。
四、产品总体方案
4.1 总体思路

本产品采用统一三级结构组织全部能力：

一级：法域
中国 / 欧盟 / 美国
二级：能力
诊断 / 起草 / 审查 / 整改
三级：专题
安全评估报告起草、PIPIA 报告起草、SCC 审查、TIA 起草、EO14117 风险审查等。

这套结构的优点是：

同一法域下的模块组织清晰；
不同法域之间的能力层级可横向比较；
便于后续扩展新专题与新法域。
五、产品功能体系
5.1 中国法域
5.1.1 诊断：合规路径诊断

面向中国数据出境场景，根据企业提交的结构化信息，判断其应适用的主要路径，例如：

安全评估
标准合同 / 认证
豁免情形

系统基于决策树规则进行初步判断，并结合知识库与大模型生成说明理由、法律依据和后续建议。

5.1.2 起草：安全评估报告起草

面向中国数据出境安全评估场景，自动生成《数据出境风险自评估报告》草案。
系统基于企业画像、出境场景、安全措施及上传文件，自动组织 8 章结构化内容，并输出 Word/Markdown 版本。

5.1.3 起草：PIPIA 报告起草

面向中国标准合同备案或个人信息保护认证路径，自动生成个人信息保护影响评估报告（PIPIA）草案。
支持结合附件解析、知识检索、章节生成和一致性检查输出成套材料。

5.1.4 审查：合同审查

对用户上传合同进行条款切分、分类和问题识别，输出条款级问题清单、整体评级和风险建议。
当前已支持“审查模式”，后续将继续扩展到“修订模式”，实现修订稿与 diff 展示。

5.1.5 整改：整改建议与行动清单

当前该能力尚未独立成模块，但相关输出已分散存在于路径诊断、报告起草与合同审查模块中。
后续将统一抽象为整改层，用于输出优先级明确的整改路线图。

5.2 欧盟法域
5.2.1 诊断：传输工具与义务诊断

面向 GDPR 跨境传输场景，判断企业更适合采用 SCC、BCR 或其他工具，并提示是否需要 DPIA、TIA 等附加义务。
该能力目前尚未独立成模块，但其逻辑已散见于 SCC、BCR、TIA 等现有专题中。

5.2.2 起草：DPIA 起草

面向高风险处理活动场景，自动生成数据保护影响评估（DPIA）草案。
系统基于处理活动描述、合法基础、风险与缓解措施等信息，组织 7 章结构生成正式报告。

5.2.3 起草：TIA 起草

面向依赖 SCC/BCR 等工具向第三国传输数据的场景，自动生成数据传输影响评估（TIA）草案。
系统重点覆盖第三国法律环境评估、补充措施评估、剩余风险结论等内容。

5.2.4 审查：SCC 审查

面向标准合同条款（SCC）使用场景，对合同与相关传输背景材料进行审查，并输出对应分析报告。

5.2.5 审查：BCR 审查

面向跨国集团 BCR 规则，对其约束力、权利义务、透明度、责任机制等多维度内容进行结构化审查，并给出问题清单和整改建议。

5.2.6 整改：补充措施与整改路线图

当前该能力主要分散在 SCC、BCR、DPIA、TIA 的 recommendation、控制措施与后续行动章节中，后续将统一抽象为欧盟法域的整改层。

5.3 美国法域
5.3.1 诊断：适用性与风险诊断

面向美国数据合规场景，判断企业是否落入 CPRA、EO14117 等规则的适用范围，并决定后续更适合进入起草还是审查专题。
该能力目前尚未独立成模块。

5.3.2 起草：CPRA 合规全景报告起草

面向加州隐私合规场景，基于企业业务模式、数据生命周期、告知同意、消费者权利流程、供应商管理等信息，生成 CPRA 合规全景报告。

5.3.3 审查：EO14117 风险审查

面向 EO14117 场景，对数据类别、接收方实体、传输链路和风险条件进行识别与审查，并输出风险分级和处置建议。

5.3.4 审查：隐私政策与数据流审查

该能力当前主要作为 CPRA 相关能力的一部分存在，用于审查隐私政策中的告知义务、数据共享与出售表述、数据流披露等内容。后续将抽象为独立审查专题。

5.3.5 整改：风险处置与整改建议

当前整改输出已存在于 EO14117 与 CPRA 的结果中，后续将作为美国法域独立整改层统一收口。

六、系统流程说明
6.1 统一主流程

产品整体运行遵循以下主流程：

用户选择法域
进入诊断、起草、审查或整改能力层
选择具体专题
填写结构化信息或上传文件
系统调用规则引擎、知识库检索和大模型生成链路
输出报告、审查意见或整改建议。
6.2 诊断类流程

适用于路径判断、适用性识别等场景：

收集用户问卷
调用规则判断逻辑
补充法律依据检索
生成结论说明与后续建议
6.3 起草类流程

适用于安全评估、PIPIA、DPIA、TIA、CPRA 等文书生成场景：

用户填写表单并上传材料
系统提取企业画像与场景信息
调用本地知识库和外部法搜服务补充依据
使用大模型按章节生成草案
输出 DOCX / MD / ZIP 等结果文件。
6.4 审查类流程

适用于合同、SCC、BCR、EO14117 等审查场景：

用户上传待审查文件或填写结构化审查项
系统进行文本切分、分类或事实提取
结合知识库与大模型识别问题
输出结构化问题清单与风险等级
6.5 整改类流程

当前整改能力主要依附于诊断、起草和审查模块的输出中。
后续将统一整合为：

风险分类
优先级排序
任务清单
后续建议与复审提示。

7.2 关键技术组件
（1）规则引擎

主要用于诊断模块中的确定性判断，如：

是否为 CIIO
是否涉及重要数据
PI / SPI 数量阈值
豁免情形匹配等。
（2）知识库 RAG

当前知识库存储于本地 regulation_articles.jsonl，覆盖中国、欧盟、美国法规条文共 1011 条。
检索方式以本地词法检索为主，在命中不足时自动调用外部法搜 queryListLaw 进行补充。

（3）大模型生成

当前通过 OpenAI 兼容协议接入腾讯混元大模型，用于：

法律说明生成
各报告章节生成
合同审查问题分析
整改建议补充。
（4）文档渲染

支持输出 Word、Markdown、PDF、ZIP、XLSX 等多种结果文件，适配不同专题的使用场景。

九、产品价值与优势
9.1 结构统一

采用“法域 → 能力 → 专题”的统一信息架构，避免传统合规工具中常见的模块堆叠和分类混乱问题。

9.2 场景真实

当前专题均围绕真实跨境数据合规场景展开，而非停留在抽象问答层面。

9.3 工程可运行

系统不仅停留在方案设计层，而是已具备可运行原型，能够输出实质性的报告和审查结果。

9.4 可扩展性强

更多法域

十、边界说明

本产品定位为合规辅助平台，而非正式法律意见出具系统。
系统输出的诊断结果、报告草案、审查意见和整改建议，主要用于提升前期分析和文书准备效率，复杂、高风险或争议性问题仍需由专业律师或合规人员进行人工复核。

这一定义有助于明确产品价值边界，也能避免将大模型输出误解为最终法律结论。
