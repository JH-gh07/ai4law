## 四、CN SCC 业务逻辑（表单驱动）

### SCCService — 全部业务在一个文件

**文件**：`backend/modules/scc/service.py`

**构成**：`SCCService` 类 + 5 个模块级函数

---

#### 主流程：generate_report(payload) → SCCResult（9 步）

```
① _build_profile(payload)
    映射7个字段 + FileParser遍历uploaded_files提取前160字
    → SCCProfile

② _generate_chapters(profile)
    2a. risk_level(is_ciio=False, contains_important=False, pii, spi)
    2b. retrieve_regulations("standard contract PIPIA {purpose} {country}", cn, scc)
    2c. 构建 context_block
    2d. generate_chapter(llm, "scc", title, context_block) × 4章
        system prompt: "中国个人信息出境标准合同备案资深合规律师"
        章节1: 审查依据说明 → (1)适用法规 (2)审查范围 (3)审查限制
        章节2: 总体合规评级 → (1)总体评级 (2)评级理由 (3)建议立即整改后备案
        章节3: 条款级问题清单 → 定位/原文/问题/风险/依据/建议
        章节4: 修订建议与行动计划 → 按优先级输出整改步骤+时限+备案检查点
    2e. _build_review_findings(profile, citations) → 4条规则findings
    2f. issues = 3条内部检查
    → (chapters[4章], issues[], findings[])

③ check_cn_alignment(report_content, receiver_country)
    检查LLM报告是否引入未提供的国家/行业
    → alignment_issues[]

④ 若对齐异常 → 追加到 issues + findings

⑤ _build_scc_template_mapping(profile, chapters, findings, date, warn)
    → 8个模板变量（contract_name/version/date/references/rating/summary/table/recommendations）

⑥ render_markdown_template(md_output, TEMPLATE_MD, mapping)

⑦ render_docx_template(docx_output, TEMPLATE_PATH, mapping)

⑧ _render_annotated_docx(payload, findings, date)
    仅当 uploaded_files 含 .docx → findings转为DocxComment → render_commented_docx

⑨ 返回 SCCResult
```

#### _build_review_findings — 4 条硬编码合规规则

```
① !has_scc_draft → HIGH: "缺失条款 — 合同主文/附件"
   建议: "先补齐SCC完整文本（含附件），再执行逐条款审查与修订。"

② spi_count > 0 → MEDIUM: "定义模糊 — 附录II 技术与组织措施"
   建议: "增加敏感个人信息最小化处理、传输加密与访问留痕条款。"

③ pii ≥ 1,000,000 或 spi ≥ 10,000 → HIGH: "与法规冲突 — 路径适用性说明"
   建议: "先完成路径复核；触发门槛时应转入安全评估流程。"

④ 均未触发 → LOW: "完善建议 — 合同整体"
   建议: "保持季度复核，并记录每次版本差异与评审意见。"
```

#### _resolve_rating — 风险评级

```
!has_scc_draft 或 findings 含 HIGH → "高风险"
findings 含 MEDIUM → "部分合规"
其他 → "基本合规"
```

### scc_rule_engine.py — 确定性规则引擎（5 组件 8 阶段）

**文件**：`backend/modules/eu_scc/scc_rule_engine.py`

**入口**：`run_eu_scc_rule_engine(doc, chain, declared_module, has_tia, has_supp) → SCCRuleEngineResult`

#### 组件 1：模块选择验证器

```
输入: SCCTransferChain + declared_module

规则表:
  exporter=controller + importer=controller → Module One (C2C)
  exporter=controller + importer=processor  → Module Two (C2P)
  exporter=processor  + importer=processor  → Module Three (P2P)
  exporter=processor  + importer=controller → Module Four (P2C)

不匹配 → HIGH finding: "模块选择错误"
```

#### 组件 2：标准条款比对器

```
标准条款定义: Clauses 7, 9, 14, 15, 16, 17, 18

15 条弱化信号正则检测（5组）：

Clause 15(a) 通知:
  "as soon as legally permissible" → 改为'法律许可时'而非'立即'
  "without undue delay to the extent legally permissible" → 增加限定条件
  "subject to applicable local law" → 受限于当地法律

Clause 15(b) 审查:
  "at the data importer's sole discretion" → 审查义务改为酌情 → restore mandatory
  "if it considers it appropriate" → 降低审查标准 → restore "reasonably considers"

Clause 15(c) 信息:
  "at the data importer's discretion" → 信息提供改为酌情 → restore full disclosure
  "to the extent reasonably practicable" → 增加限定条件

Clause 14 评估:
  "to the best of its knowledge" → 降低评估义务 → restore objective obligation

Clause 9 授权:
  "general written authorization" → 一般授权而非具体授权 → require specific prior

逐Clause匹配 → 命中 → HIGH SCCFinding + 标记clause.has_deviation
```

#### 组件 3：附录审查器

```
Annex I.A — 主体完整性:
  is_incomplete → MEDIUM finding; 缺 name/role → MEDIUM; party < 2 → MEDIUM/HIGH

Annex I.B — 传输描述 + 特殊类别:
  数据类别过泛(订单/客户/交易) → LOW finding
  health/medical 词但未声明 special category → HIGH finding (GDPR Art.9)

Annex II — TOMs:
  tom_items 为空 → HIGH finding

Annex III — 子处理者: 可为空（合法）
```

#### 组件 4：TIA + 补充措施审查器

```
① 第三国识别:
   遍历 transfer_chain 所有 locations → 匹配 22国充分性表
   非充分性国家 → third_country_locations[]

   22国充分性表:
   充分性: UK, Japan, South Korea, Switzerland, Canada, Argentina, Israel,
           New Zealand, Uruguay, Andorra, Faroe Islands, Guernsey, Jersey, Isle of Man
   非充分性: United States, India, China, Russia, Brazil, Singapore, Australia, Serbia

② TIA 检查:
   has_third_country AND !has_tia → HIGH finding
   has_third_country AND Clause 14 weakened → HIGH finding

③ Schrems II 补充措施检测:
   技术措施: E2E加密 / EU持钥 / BYOK / zero-access / zero knowledge / 端到端加密
   合同措施: 政府访问通知 / 挑战非法请求 / 透明度报告 / warrant canary
   组织措施: 数据最小化 / 独立年度审计 / 隐私影响评估 / 密钥管理分离
   不足 → HIGH finding (含三类检测结果)

④ 美国特有风险:
   location 匹配 us/usa/amazon/aws/google cloud/azure/microsoft
   AND 技术+合同措施不完整 → HIGH finding (CLOUD Act / FISA 702)
   建议: E2E加密+EU持钥, 合同挑战FISA, 透明度报告

⑤ 子处理者链条:
   逐sp_name → 匹配第三国充分性表
   非充分性国家 → MEDIUM finding (Clause 9授权+TIA+onward transfer)
```

#### 组件 5：总体风险评分

```
取所有 findings 的最高严重度:
  HIGH in severities → "HIGH"
  MEDIUM in severities → "MEDIUM"
  其他 → "LOW"
```

#### 主流程：generate_report(payload) → SCCReviewResult（12 步）

```
① parse_scc_document(scc_text, module, exporter, importer)
   → SCCDocument (Clauses 1-18 + 4 Annexes)

② _build_transfer_chain(exporter, importer, doc)
   → SCCTransferChain (主体+子处理者+存储/访问位置)

③ run_eu_scc_rule_engine(doc, chain, module, has_tia, has_supp)
   组件1: 模块验证 → ModuleValidation
   组件2: 条款比对 → ClauseComparison (15条弱化信号)
   组件3: 附录审查 → AnnexReview (4个Annex)
   组件4: TIA审查 → TIAReview (22国+Schrems II+US+子处理者)
   组件5: 风险评分 → overall_rating
   → SCCRuleEngineResult

④ trace.record("rule_engine_result")

⑤ WorkflowPipeline.run(payload, task_id, trace) — 12 步管线

   ⑤-extract: identity (payload原样)
   ⑥-evaluate: rule_result (规则引擎输出)
   ⑦-build_facts: 22条 FactItem
   ⑧-retrieve_regulations: RAG (GDPR Article 46 + Schrems II + module)
   ⑨-build_attachment_notes: FileParser提取前160字
   ⑩-build_issues: 6类 IssueItem
   ⑪-build_evidence: fact↔issue←evidence链
   ⑫-build_context_pack: GenerationContextPack
   ⑬-generate_chapters: 4章 LLM / placeholder
        LLM可用: generate_chapter(llm, "eu_scc", title, ctx, citations)
        LLM不可用: _render_placeholder → 结构化占位内容
          (含模块信息/评级/条款细节/findings明细)
   ⑭-check_consistency: 3条规则
   ⑮-render_artifacts: .md + .docx + findings.json +
                        rule_engine_result.json + issues.json +
                        evidence.json + 批注版.docx

⑥ 返回 SCCReviewResult
```

### check_cn_alignment — 输入对齐校验

check_cn_alignment(report_content, *, industry=None, is_ciio=None,
                   contains_important_data=None, receiver_country=None):

### risk_level — 风险等级计算

**文件**：`backend/common/risk/scoring.py`

```
risk_level(is_ciio, contains_important_data, pii_count, spi_count):
  is_ciio 或 contains_important_data → HIGH
  pii ≥ 1,000,000 或 spi ≥ 10,000 → HIGH
  否则按比例 → MEDIUM / LOW
```

### generate_chapter — LLM 章节生成

**文件**：`backend/common/llm/module_generator.py`

```
generate_chapter(llm_client, module, chapter_title, context_block, citations):

  组装 system prompt + chapter instruction + context_block + strict_constraint
  调用 llm_client.chat()
  后处理: ensure_paragraph_citations(citations)

  "你是一名专注于中国个人信息出境标准合同备案的资深合规律师..."

EU_SCC 模块 system prompt:
  "你是一名专注于欧盟数据保护与跨境传输合规的资深律师..."
```

## 十一、关键设计决策

| 维度 | 实现方式 |
|------|---------|
| 双引擎架构 | CN SCC 表单驱动 (简单场景)，EU SCC 文档驱动 (深度场景) |
| EU SCC 管线 | WorkflowPipeline — 14注入点策略模式，16步执行 |
| CN SCC 规则 | 4条硬编码 — 确定性、不可变 |
| EU SCC 规则 | 5组件确定性引擎 — 全部规则硬编码，无LLM依赖 |
| EU SCC 解析 | 正则+启发式 — 模块识别→章节分拆→18条Clause→4个Annex |
| EU SCC 条款比对 | 6组关键条款 + 15条弱化信号正则 |
| EU SCC TIA | 22国充分性表 + Schrems II 3类措施 + US风险 + 子处理者链条 |
| 批注版 | DocxComment → render_commented_docx — 两个模块共用 |
| CN SCC 对齐 | check_cn_alignment — 防止LLM引入未提供事实 |
| 风险评级 | 取最高严重度 (两个模块相同) |
| 全链路trace | TraceRecorder (仅EU SCC) |
| 异步任务 | InMemoryTaskManager (两个模块相同) |
