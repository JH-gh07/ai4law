> 模块路径: `backend/modules/assessment/`
> 法律框架: 中国《个人信息保护法》《数据安全法》《数据出境安全评估办法》《促进和规范数据跨境流动规定》

## 一、总体架构概览

### 1.1 模块定位

安全评估模块是整个 ai4law 平台的**核心文书生成模块**。用户从合规路径诊断模块确认应走安全评估路径后，在此提交企业数据处理信息，系统通过 **WorkflowPipeline 15 步流水线**生成：
- 内部 8 章分析报告（MD + DOCX）
- 官方 3 节申报草案（MD + DOCX）
- 中间产物（facts / issues / evidence / legal_grounding / writing_strategy / citation_map 等）
- 批注版内部审查报告

### 1.2 两层架构（迭代 v3 新增）

```
用户输入 AssessmentRequest
        │
        ├─[第0层] 输入归一化 + 合规推理
        │   ├─ InputNormalizationAgent   → 字段状态标记 (provided/missing/inferred)
        │   ├─ AttachmentParsingAgent    → 合同条款 + 附件证据抽取
        │   ├─ DataClassificationAgent   → 数据定性 + 重识别风险评估
        │   └─ build_compliance_reasoning() → 合规推理矩阵
        │
        └─[第1层] WorkflowPipeline 15 步流水线
            ├─ extract_profile
            ├─ evaluate_diagnosis      → _DiagnosisStub (不再重做路径判断)
            ├─ validate_path           → 仅做一致性提示，不阻断
            ├─ build_facts
            ├─ retrieve_regulations
            ├─ build_attachment_notes
            ├─ build_issues            → 18 个 IssueItem + 三态分类
            ├─ build_evidence
            ├─ retrieve_per_issue
            ├─ build_context_pack      → 含 legal_grounding + writing_strategy + citation_registry
            ├─ generate_chapters       → 8 章内部分析 + 3 节官方报告
            ├─ check_consistency       → 6 类检查
            ├─ repair_chapters         → ControlledRepairAgent
            ├─ check_alignment
            └─ render_artifacts
```

## 二、迭代 v3 新增功能详解

### 2.1 路径判断弱化 (service.py)

**改动前**: `_evaluate_diagnosis()` → `DiagnosisService.evaluate()` → 重新做路径判断，可能阻断生成

**改动后**: `_evaluate_diagnosis()` → `_DiagnosisStub(recommended_path="security_assessment")` → 始终生成

```python
class _DiagnosisStub:
    def __init__(self, recommended_path: str = "security_assessment"):
        self.recommended_path = recommended_path
        self.rationale = "上游路径诊断模块已判定进入安全评估路径，本模块仅负责文书生成。"
```

### 2.2 扩展输入模型 (schema.py)

**新增 9 个辅助模型**:

| 模型 | 核心字段 |
|------|---------|
| `DataInventoryItem` | name, description, data_subject, personal_info_type, is_important_data_candidate, necessity, example, volume, retention_period, remarks |
| `RecipientInfo` | name, country_or_region, role, relationship, security_certifications[], audit_reports[], legal_environment_summary, processing_purpose, processing_method, storage_location |
| `DownstreamProcessor` | name, country_or_region, role, processing_activity, contract_covered, onward_transfer_constraint |
| `LegalDocumentReview` | document_name, clause_coverage{6项核心条款}, raw_clause_refs[], missing_items[], risk_level |
| `SecurityCapability` | management_measures[], technical_measures[], certifications[], compliance_records[] |
| `ComplianceHistory` | has_penalty, penalty_time, penalty_reason, rectification_status |
| `PersonalInfoProtection` | separate_consent_status, notice_content, rights_response, archive_evidence |
| `SystemLink` | domestic_systems[], transfer_links[], transit_locations[], overseas_systems[] |
| `SelfAssessmentInfo` | start_date, end_date, participating_departments[], preliminary_conclusion |

`CompanyProfile` 同步扩展以携带这些结构化字段。

### 2.3 Issue 三态分类 (issue_builder.py)

每个 Issue 的 `recommended_action` 前缀嵌入确定类型:

| 类型 | 典型 Issue | 对外表达策略 |
|------|-----------|-------------|
| `confirmed_issue` | CIIO、重要数据、数量阈值 | "当前...未覆盖..." |
| `suspected_issue` | 接收方安全证据缺失、合同缺口、同意记录缺失 | "由于未提供相关材料，尚无法确认..." |
| `default_review_item` | 材料清单不完整、内部审批缺失 | "建议在正式申报前核验..." |

### 2.4 合规推理矩阵 (compliance_reasoning.py)

`ComplianceReasoningItem` 为 9 个核心评估维度提供结构化推理:

```
target: 境外接收方安全保障能力
user_claim: 用户声称情况
fact_status: user_claim_only | partially_supported | fully_documented
reasonableness: 方向合理，但表述过于概括
ambiguity: 未说明具体认证标准、有效期、审计范围
legal_risk: 接收方安全保障能力证明不足以支撑报告中的正面结论
possible_non_compliance: 可能难以满足安全评估办法对境外接收方安全能力的要求
correct_expression: 用户已说明接收方遵循相关标准，但尚需补充认证证书或审计报告予以佐证。
external_claim_allowed: false
```

### 2.5 引用质量校验 (citation_quality.py)

`validate_citation_for_issue(issue_id, category, title, article) → CitationSupportLevel`:

| 等级 | 定义 | 外部报告可用 |
|------|------|------------|
| `exact_support` | 标题和条款号都匹配 issue 类别所需法规 | ✅ |
| `partial_support` | 标题匹配但条款号不匹配 | ✅ |
| `background_only` | 属于中国数据法体系但非直接相关条款 | ❌ |
| `irrelevant` | 无关法规 | ❌ |

内置规则矩阵:
- `consent` → 必须有 PIPL Art.39 (exact_support)
- `legal_document/onward_transfer` → 必须有 Assessment Measures Art.9
- `data_scope` → 必须有 Assessment Measures Art.5

### 2.6 7 个 Specialist Agent (agents/)

**Agent 1: InputNormalizationAgent** — 输入归一化
- 按官方模板 schema 逐字段检查状态 (provided/missing/ambiguous/inferred/conflicting)
- 生成 missing_critical_fields 和 clarification_questions
- LLM 增强: 对缺失字段尝试推断

**Agent 2: AttachmentParsingAgent** — 附件深度解析
- 合同: 检查 6 项核心条款（第九条要求）
- 同意记录: 搜索单独同意/明示同意关键词
- 每项返回 covered/partial/missing/unclear + 置信度

**Agent 3: DataClassificationAgent** — 数据定性
- 内置 SPI 指标词库（金融账户、行踪轨迹、医疗健康等）
- 内置重要数据候选指标词库（金融交易、车辆轨迹、能源等）
- 逐项输出: 是否个人信息/敏感个人信息/重要数据候选 + 重识别风险等级

**Agent 4: LegalCitationAgent** — 引用校验
- 汇总所有 issue 的引用支撑等级
- 生成弱引用警告 (background_only/irrelevant)
- 过滤外部报告可用引用 (仅保留 exact/partial)

**Agent 5: DocumentPlanningAgent** — 文书规划
- 为官方 7 个 section 生成写作计划
- 每个 section: must_cover / confirmed_facts / issues_to_disclose / allowed_positive_claims / forbidden_claims / required_citations / writing_instruction

**Agent 6: ExpressionCalibrationAgent** — 表达校准
- 检测 8 种过度承诺模式 (完全符合、已充分证明、不存在风险等)
- 检测内部表述泄露
- 自动替换为审慎表述

**Agent 7: ControlledRepairAgent** — 受控修复
- 区分 repairable (缺引用/禁用表达/内部泄露) vs blocking (缺事实/降风险/改变证据)
- 修复后四检查: new_fact_injection / risk_downgrade / citation_drift / material_claim
- 阻塞项不修复，标记为 unresolved

## 三、15 步 WorkflowPipeline 逻辑流程

### 步骤 1: extract_profile
`ProfileExtractor.extract(payload) → CompanyProfile`
- FileParser 解析上传文件
- `parse_attachment_metadata()` 分类并提取附件元数据
- 携带新的结构化字段 (data_inventory_items, recipient_info 等)

### 步骤 2: evaluate_diagnosis
`_DiagnosisStub(recommended_path="security_assessment")`
- **迭代 v3 改动**: 不再调用 DiagnosisService
- 始终返回 security_assessment 路径

### 步骤 3: validate_path
仅做"上游路径一致性提示"，不阻断生成。`path_check_mode` 默认 `generate_only`。

### 步骤 4: build_facts
`build_assessment_facts(request, profile, diagnosis) → list[FactItem]`
- Schema facts (9 个核心字段, 置信度 0.6, evidence_status=user_claim_only)
- Attachment note facts (置信度 0.8)
- Diagnosis facts (置信度 1.0)
- **迭代 v3 新增**: 从扩展字段中提取 data_inventory_items / recipient_info 等事实

### 步骤 5: retrieve_regulations
`AssessmentRetriever.search(profile) → list[RegulationHit]`
- 通过 RetrievalOrchestrator 从 cn_assessment 索引检索
- 备用: `retrieve_regulations()` 旧版检索

### 步骤 6: build_attachment_notes
从 profile 提取 attachment_metadata 和 extracted_notes。

### 步骤 7: build_issues
`build_assessment_issues(facts, diagnosis, regulations, attachment_notes) → list[IssueItem]`
- 18 个 Issue: 路径问题、数据范围、文件问题、接收方问题、同意问题、其他
- 附件证据扫描 (`_attachment_evidence()`) 可明智地降低部分 Issue 严重性
- **迭代 v3 新增**: 三态分类标记嵌入 recommended_action

### 步骤 8: build_evidence
`build_assessment_evidence(facts, issues, regulations, diagnosis) → (updated_issues, evidence_chain)`
- 为每个有有效事实引用的 Issue 创建 EvidenceItem
- 置信度: 基于严重性和法规引用计算

### 步骤 9: retrieve_per_issue
对 HIGH/BLOCKER Issue 调用 DeliLegal search_laws + search_cases。

### 步骤 10: build_context_pack
组装 `GenerationContextPack`:
- `legal_grounding`: 三级法规重排序 (0→0.98 分)
- `writing_strategy`: 内部/外部表达 + 禁用表达
- `generation_basis_pack`: 按章节打包事实/法规/策略/证据
- `citation_registry`: 引用注册表

### 步骤 11: generate_chapters
`AssessmentChapterGenerator.generate() → list[ChapterContent]`
- 8 章内部分析 (LLM temperature=0.2, max_tokens=800)
- 每章独立的上下文块 (含章节特定事实/法规/问题/策略)

### 步骤 12: check_consistency
`ConsistencyChecker.check_with_context() → list[str]`
6 类检查: 基本检查、上下文包引用完整性、报告与上下文对齐、禁用表达、内部泄露、user_claim_only 滥用、案例引用泄露

### 步骤 13: check_alignment
`check_cn_alignment(report_content, receiver_country, ...) → list[str]`
检查 CIIO 幻觉、重要数据幻觉、行业幻觉、国家/地区幻觉。

### 步骤 14: repair_chapters
`run_repair_pass(chapters, issues, profile, context_pack, max_retries=3)`
- 可修复: 缺引用、禁用表达、内部泄露、user_claim 正面滥用
- 阻塞: 缺事实引用、缺法规引用、缺证据引用、材料矛盾

### 步骤 15: render_artifacts
`AssessmentReportRenderer.render() → dict[str, str]`
- 内部 8 章: MD + DOCX (模板渲染)
- 官方 3 节: MD + DOCX (external_report_generator)
- 中间产物: issue_list (JSON/XLSX), evidence_chain, material_checklist, facts, path_judgment, legal_grounding, writing_strategy, generation_basis_pack, citation_map
- 内部 AI 审查: internal_review.md
- ZIP 打包
