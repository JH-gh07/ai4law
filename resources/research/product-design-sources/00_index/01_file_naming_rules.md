# 法律文件命名规则

## 基本格式

```text
用途序号_用途类型_同类序号_中文说明.扩展名
```

## 用途序号

| 用途序号 | 用途类型 | 含义 |
|---|---|---|
| `01` | `RULE` | 规则判断材料，用于 true/false、路径适用性或风险识别 |
| `02` | `SOURCE` | 法规、监管指南、官方模板、判例或权威来源 |
| `03` | `TEMPLATE` | 文书、报告、合同或表格模板 |
| `04` | `CLAUSE` | 条款审查要点、标准条款、示例条款 |
| `05` | `CHECKLIST` | 输入清单、字段截图、材料清单、检查表 |
| `99` | `ORIGINAL` | 原始统筹文档或未拆分母文档 |

## 示例

```text
01_RULE_001_安全评估触发条件.md
02_SOURCE_001_个人信息保护法第38条.md
03_TEMPLATE_001_数据出境风险自评估报告模板.docx
05_CHECKLIST_001_CPRA输入截图_4.2.png
```

## 整理原则

1. 一个业务子类对应一个文件夹，避免全库混放。
2. 文件命名优先表达用途，其次表达内容。
3. 同一用途下按 `001/002/003` 排序。
4. 后续做 RAG、引用卡片和规则绑定时，优先使用该文件名作为人工可读来源编号。
5. 如果同一文件同时适用于多个模块，先放入最主要用途目录；需要复用时在索引中标注，不复制多份。
