# “合规路径诊断”测试案例及预期输出

“合规路径诊断”测试案例及预期输出
测试案例一：电商用户数据出境（标准合同/认证路径） 
背景：中国境内一家名为“跨境优品”的中型跨境电商平台，计划将过去半年的订单数据同步至其位于新加坡的亚太数据中心，用于优化区域物流算法和精准营销。
用户输入详情：
	•	步骤一：识别“重要数据”出境义务
	•	用户回答：否。公司确认，本次传输的数据为消费者订单信息，不涉及《工业数据分类分级指南》等行业目录中定义的、或公司自认的“重要数据”。
	•	步骤二：识别“个人信息”与基础豁免
	•	用户回答：是。传输的数据包含：用户姓名、收货地址、联系电话、商品订单号、购买时间、商品金额、支付方式（已去标识化处理为支付渠道编号，不含银行卡号）。
	•	步骤三：核查法定豁免情形
	•	用户选择：均不属于。公司确认，本次传输非履行与单个消费者的具体合同所必需（合同已履行完毕），也非人力资源管理或紧急情况。公司注册地不在自贸试验区内。
	•	步骤四：确认数据处理者身份（是否CIIO）
	•	用户回答：否。“跨境优品”为普通电商平台，未被认定为关键信息基础设施运营者。
	•	步骤五：区分与量化个人信息类型
	•	用户选择：A. 仅涉及一般个人信息。确认不包含生物识别、健康、行踪轨迹等敏感信息。
	•	步骤五（A）子路径：量化一般个人信息
	•	用户回答：10万人以上，但未达到100万人。经统计，自今年1月1日起，涉及出境的去重用户数量约为45万人。
预期输出：
	•	核心结论：应当通过订立个人信息出境标准合同或者通过个人信息保护认证的途径。
	•	结构化诊断报告（主要内容）：
	•	用户答案摘要：表格列明上述所有问题和答案。
	•	判定逻辑树：展示从“不涉及重要数据” -> “涉及个人信息” -> “不适用豁免” -> “非CIIO” -> “一般个人信息45万人” -> 触发《规定》第八条（10万-100万一般个人信息）的逻辑链条。
	•	逐条法规依据：重点引用并解释《促进和规范数据跨境流动规定》第八条。
	•	核心风险提示：提示需确保已履行对45万用户的告知与单独同意义务；标准合同需依法备案。
	•	后续行动建议：建议启动个人信息保护影响评估，并着手准备《个人信息出境标准合同》的订立与备案材料。
测试案例二：医疗研究数据出境（安全评估路径） 
背景：中国“前沿生命科技研究院”与欧盟某大学合作进行一项罕见病研究，需将1.5万名中国患者的脱敏医疗记录（含诊断结果、用药史、基因测序数据摘要）传输至欧盟的合作方服务器进行分析。
用户输入详情：
	•	步骤一：识别“重要数据”出境义务
	•	用户回答：不知道。系统启动辅助判断子流程。
	•	询问行业领域：用户选择“卫生健康”。
	•	询问数据性质：用户描述“涉及1.5万名罕见病患者的脱敏医疗记录和基因测序数据摘要，用于国际联合医学研究”。
	•	判断与反馈：系统匹配《卫生健康行业数据分类分级指南》，发现“涉及1万人的特定药品实验数据或族群生物特征数据”可被视为重要数据。系统提示：“根据您提供的信息，该数据可能涉及重要数据（符合‘涉及1万人的族群生物特征数据’特征）。基于审慎原则，系统建议按涉及重要数据处理。”并引导用户选择“是”。
	•	步骤二：因步骤一选择“是”，主流程立即终止。
预期输出：
	•	核心结论：必须申报数据出境安全评估。
	•	结构化诊断报告（主要内容）：
	•	用户答案摘要：包含步骤一的原始答案及辅助判断子流程中的详细问答记录。
	•	判定逻辑树：展示“涉及重要数据” -> 立即触发《规定》第七条的短路逻辑。
	•	逐条法规依据：重点引用并解释《促进和规范数据跨境流动规定》第七条，并结合《数据安全法》第二十一条及《卫生健康行业数据分类分级指南》的相关描述，说明将其判定为“可能涉及重要数据”的理由。
	•	核心风险提示：强调重要数据出境的风险极高，必须进行安全评估；提示即使数据已脱敏，仍需谨慎评估重标识化风险。
	•	后续行动建议：立即启动数据出境风险自评估，准备包括《数据出境风险自评估报告》在内的全套申报材料，通过“数据出境申报系统”提交。
测试案例三：匿名地图数据出境（豁免路径） 
背景：一家中国自动驾驶技术公司“智驾未来”，向其德国母公司提供在中国境内采集的、已进行完全匿名化处理（无法关联到特定车辆或个人）的车辆传感器数据包，用于改进全球自动驾驶算法模型。
用户输入详情：
	•	步骤一：识别“重要数据”出境义务
	•	用户回答：否。公司确认，该匿名传感器数据包不包含地理精度达到保密级别的测绘信息，不涉及国家秘密或公司认定的重要数据。
	•	步骤二：识别“个人信息”与基础豁免
	•	用户回答：不知道。系统启动辅助判断子流程。
	•	提供示例清单：系统展示个人信息清单。
	•	判断与反馈：用户逐一核对后确认，数据包中不包含任何清单所列信息（如车辆VIN码、车牌、驾驶员信息等均已去除且无法复原）。系统提示：“根据您的描述，该数据不包含个人信息。”并引导用户选择“否”。
	•	步骤三：因步骤二选择“否”，主流程立即终止。
预期输出：
	•	核心结论：属于豁免情形，不需要申报数据出境安全评估、订立个人信息出境标准合同、通过个人信息保护认证。
	•	结构化诊断报告（主要内容）：
	•	用户答案摘要：包含步骤一、二的原始答案及辅助判断子流程中的详细核对记录。
	•	判定逻辑树：展示“不涉及重要数据” -> “不包含个人信息” -> 触发《规定》第三条豁免的逻辑。
	•	逐条法规依据：重点引用并解释《促进和规范数据跨境流动规定》第三条，并援引《个人信息保护法》第四条关于“匿名化”的定义，支持“不包含个人信息”的判断。
	•	核心风险提示：提示“匿名化”需达到无法识别的标准，并建议公司留存匿名化技术处理的有效性证明，以备监管核查。
	•	后续行动建议：建议内部完善数据匿名化处理流程的技术文档和管理制度，确保合规闭环。
这三个案例分别覆盖了标准合同/认证、安全评估、豁免三大核心路径，并测试了“不知道”场景下的辅助判断功能，可以较为全面地验证“合规路径诊断”模块的运行逻辑。
